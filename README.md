# Obsidian vault セットアップ

タスク管理・メモ・議事録など業務全体を1つのvaultで管理するための構成。`type` プロパティでBasesを絞り込むため、ノートをどのフォルダに置いても正しく集計される。コミュニティプラグインは使わず、Obsidianコア機能（Bases・タグペイン・全文検索・テンプレート）のみで完結する。

## 前提

- Obsidian **1.11 以降**（Bases がコア機能として使えることに加え、`設定 → ファイルとリンク → Default file to open` の `Daily note` オプションが1.11で追加されているため）。`設定 → 一般` で確認する。

## 5つのBaseの役割

デイリーノート（`92_Template/daily.md`）の「全体管理」見出しには各Baseの一部のビューだけを埋め込んだダイジェスト（プロジェクト一覧・エリア一覧・最近の議事録・最近のメモ）がまとまっているので、もっと詳しく見たい時は該当のBaseファイルを直接開く。それぞれ「何を知りたい時に見るものか」で使い分ける。

| Base | 答える問い | 直接開いて使う場面 |
|---|---|---|
| `タスクBase.base` | 今、何をすべきか | 「今日・今週やることを確認したい」「特定の案件の残作業だけ見たい」時に、TOPには出ていない他のビューに切り替えて使う |
| `プロジェクトBase.base` | 今動いている案件はどれか、状況は | 新しい案件を始める前に「今どれだけ案件を抱えているか」を確認したい時 |
| `エリアBase.base` | 継続的に責任を持っている業務は何か | プロジェクトと違い「完了」が無い運用・保守業務の棚卸しをしたい時 |
| `議事録Base.base` | いつ・誰と・何を話したか | 「あの会議いつだっけ」を後から探す時 |
| `メモBase.base` | 最近書き殴ったものは何か | 正式なタスク化・整理をする前の、書きっぱなしメモを新しい順にざっと見返したい時 |

タスクとプロジェクト／エリアの違いは「チェックできる単位（タスク）」か「状態だけを持つ器（プロジェクト・エリア）」か、プロジェクトとエリアの違いは「いずれ完了するか（プロジェクト）」か「終わりが無いか（エリア）」かで判断する。

`タスクBase.base` は1つのファイルの中に7つのビュー（タブ）を持つ。それぞれ同じタスクを別の切り口で並べ替えているだけで、データそのものは共通。

- **タスク一覧**: status（todo/doing/done）別にグルーピング。何が滞留しているか俯瞰する
- **期限順**: 完了以外を期限が近い順に並べる。日々一番よく使うのはこれ
- **優先度別**: 完了以外を優先度でグルーピング。緊急度でなく重要度で見たい時
- **コンテキスト別**: `context` でグルーピング。特定の案件・エリアに取り組んでいる時、その残作業だけ見たい時
- **チェック日順**: 完了以外を`check`（再確認日）が近い順に並べる。保留中・返答待ちのタスクについて、そろそろ再確認すべきものを見る時
- **期限切れ・本日期限**: 完了以外かつ`due`が今日以前（期限切れを含む）のものだけに絞り込む。今すぐ対応すべき期限のタスクだけを見る時
- **本日チェック**: 完了以外かつ`check`が今日以前のものだけに絞り込む。今日以前が再確認日のタスクだけを見る時

`議事録Base.base`・`メモBase.base` はそれぞれ2つのビューを持つ。`議事録Base.base` は「議事録」（全件、`date`降順）と「最近の議事録」（直近7日以内の`date`に絞り込み）、`メモBase.base` は「メモ」（全件、`file.mtime`降順・20件まで）と「最近のメモ」（直近7日以内に作成＝`file.ctime`に絞り込み）で構成される。

## プロパティの使い方

### 命名規則

プロパティ名は英語・小文字・単語1つで統一している（`type` / `status` / `priority` / `due` / `context` / `tags` / `goal` / `date` / `check`）。

新規プロパティを追加する際は、**テンプレート（`92_Template/*.md`）・対応する `.base` ファイル・このREADMEの表**の3点を同時に更新すること。過去に `check` というプロパティがテンプレートに定義されないまま特定のInboxノートにだけ存在してしまった実例があり、この3点セット更新ルールはその再発防止のために定めている。

### 型と値の統一表

| プロパティ | 型 | 許容値 | 用途 |
|---|---|---|---|
| `type` | 文字列（スカラー） | `task` / `project` / `area` / `meeting` | どのBaseに集計されるかを決める振り分けキー |
| `status` | 文字列（スカラー。YAMLリストにしない） | task: `1_todo` / `2_doing` / `3_done`。project: `1_active`（他の値は現状のテンプレート・サンプルには無い） | 進捗状態。task・projectの既定のグルーピング軸（areaは`status`を持たない） |
| `priority` | 文字列（スカラー） | `1_high` / `2_medium` / `3_low` | 重要度。task・projectの「優先度別」ビューのグルーピング軸（areaは`priority`を持たない） |
| `due` | 日付文字列 `YYYY-MM-DD` | - | 期限。task・projectに存在し、areaには無い（終わりが無い業務のため） |
| `check` | 日付文字列 `YYYY-MM-DD` | - | 再確認日。保留中・返答待ちのタスクについて、もう一度状況を確認する日付を入れる。`due`（作業の締切）とは別の、フォローアップ／スヌーズ用途のプロパティ |
| `date` | 日付文字列 `YYYY-MM-DD` | - | ノート作成日。task・meeting・`memo`に存在し、いずれもテンプレートの`{{date}}`で作成時に自動入力される |
| `context` | 文字列（wikilink形式、例: `"[[A社ネットワーク更改]]"`） | - | 紐づく案件・エリアへのリンク。全typeに共通の任意プロパティ。task・meetingで指定すると、プロジェクト／エリア側のバックリンクと`タスクBase.base`「コンテキスト別」ビューに自動集計される |
| `tags` | 文字列のリスト | 自由 | 分類用タグ。全typeに共通の任意プロパティ |
| `goal` | 文字列 | 自由 | 達成すべきゴール。task・projectに存在する任意プロパティ |

議事録の出席者は`attendees`プロパティではなく、本文の`## 出席者`見出しに書く（`attendees`プロパティは廃止）。

### Baseごとの使い分け表

`●` = テンプレートに初期値がある必須プロパティ（`{{date}}`のようなテンプレート変数も含む）。`○` = テンプレートでは空欄の任意プロパティ。空欄 = そのtypeにはプロパティ自体が無い。

| プロパティ | task | project | area | meeting | `memo` |
|---|---|---|---|---|---|
| `type` | ● | ● | ● | ● |  |
| `status` | ● | ● |  |  |  |
| `priority` | ● | ● |  |  |  |
| `due` | ○ | ○ |  |  |  |
| `check` | ○ |  |  |  |  |
| `date` | ● |  |  | ● | ● |
| `context` | ○ | ○ | ○ | ○ | ○ |
| `tags` | ○ | ○ | ○ | ○ | ○ |
| `goal` | ○ | ○ |  |  |  |

area は終わりが無い業務のため `due`・`status`・`priority` を持たない。meeting の `date` はテンプレートの `{{date}}` で作成時に自動入力される。`memo`（`10_Inbox`）は `type` プロパティを持たない（`メモBase.base` はフォルダ基準の絞り込みのため）。

`10_Inbox`の`memo`は`date`・`context`・`tags`のみを持ち、`type`別のプロパティ体系（`status`・`priority`等）は持たない。デイリーノートは`date`・`tags`を持ち、`type`別のプロパティ体系は持たない（詳細は前掲「5つのBaseの役割」および「業務での使い方」を参照）。

### 運用フロー

- 新規ノートは必ずテンプレート挿入（`92_Template/*.md`）から作成し、既定のプロパティ欄を埋める形にする。空のプロパティ（`due`/`check`/`context`等）は該当が無ければ空欄のままでよい
- `context`のようにノートを参照する値は手入力せず、プロパティパネルまたは`[[`の入力補完から既存ノートを検索して選ぶ（タイプミス防止）
- 新規プロパティを追加する場合は、上記「命名規則」の3点セット更新ルール（テンプレート・`.base`ファイル・このREADMEの表）に従う

## 業務での使い方（操作手順）

- **メモを気軽に追加**: `Ctrl+N` → 割り当てたホットキー（例: `Ctrl+Shift+N`）でテンプレート挿入し `memo` を選択 → そのまま書く。作成日（`date`）は自動入力されるので`tags`だけ埋める。探す時は全文検索（`Ctrl+Shift+F`）かタグペイン
- **Inboxのメモをトリアージして移動する**: `10_Inbox`のメモが実際のタスク/プロジェクト/エリア/議事録として具体化したら、対応するテンプレート（`92_Template/*.md`）を挿入して`type`等のプロパティを埋める → 割り当てたホットキー（例: `Ctrl+M`）で「ファイルを別のフォルダへ移動」を実行し、対応フォルダ（例: `30_Work/`）へ移動する。Basesは`type`プロパティでフォルダに依存せず集計するため機能的には移動は必須ではないが、`10_Inbox`を「まだ手を付けていないものだけの場所」として保つために移動する
- **タスクを1件追加**: `Ctrl+N` → タイトル入力 → テンプレート挿入で `task`。作成日（`date`）は自動入力される。`status`/`priority`はそのままでよく、`due`/`check`/`context`/`goal`は空欄のままでもよい
- **会議に出て議事録を取る**: 会議前に `Ctrl+N` → テンプレート挿入で `meeting`（`date`は自動で当日）→ 会議中は議題・決定事項を書き、アクションアイテムは `- [ ] [[新規タスク名]]` とリンクだけ書く → 会議後にリンクをクリックしてテンプレート挿入で `task` 化する
- **新しい案件が立ち上がる**: `Ctrl+N` → テンプレート挿入で `project`。タスク・議事録側で`context`にこの案件をリンクすれば、自動的にバックリンクパネルと `タスクBase` の「コンテキスト別」ビューに集まる
- **障害対応・突発対応**: まずメモと同じ手順で書き留める。追跡が必要ならタスク化し、`context` に該当エリアをリンクする
- **リンクは `[[` の入力補完、または各ノート上部の「プロパティ」パネルから既存ノートを検索して選ぶ**と、タイプミスを防げて早い
- **メモをInboxに置きっぱなしにするのは問題ない**（検索・タグで見つかる）。対応が必要だと気づいたら、そのメモを具体化して対応フォルダへ移動する（詳細は「Inboxのメモをトリアージして移動する」を参照）
- **1日の作業はデイリーノートで回す**: `Ctrl+D`→デイリーノートを開く。`92_Template/daily.md` は上から「スケジュール」→「今日のTodo」（今すぐ対応が必要なタスクだけに絞った埋め込みビュー: `タスクBase.base`の「期限切れ・本日期限」「本日チェック」）→「メモ」→「振り返り」の順で当日の実行分がまとまり、その下に「前日の記録」（前日のTodo・前日のメモ・前日の振り返りの埋め込みビュー）と「全体管理」（プロジェクト一覧・エリア一覧・最近の議事録・最近のメモの埋め込みビュー）が続く構成のため、全体俯瞰とその日の実行管理の両方をデイリーノート1つで完結できる。「前日の記録」の3つの埋め込みは`YESTERDAY`という固定のプレースホルダー文字列を参照しているため、ノート作成後に`Ctrl+H`（コアの「検索と置換」）で`YESTERDAY`を実際の前日の日付（例: `2026-07-29`）に一括置換してから使う

## リンク（`[[...]]`）は使うか

使う。ただし全ノートを密にリンクで結ぶ設計ではなく、**「あとで自動的に集計・逆引きしたい関係」だけ**リンクにする。集計の必要が無い所を無理にリンクで結ぶ必要は無い。

具体的にリンクを使う場面:

1. **タスク・議事録 → プロジェクト／エリア**（`context: "[[案件名]]"`）
   最も重要な用途。これを書くだけで、プロジェクト／エリアノート側のバックリンクパネルと `タスクBase.base` の「コンテキスト別」ビューの両方に自動集計される。「この案件の残作業・議事録は何か」を後から見たい時のために書く。
2. **議事録 → タスク**（アクションアイテム欄: `- [ ] [[タスクノート名]]`）
   会議で決まったアクションアイテムを、その場ではリンクとして書くだけでよい（対象のノートがまだ無くても書ける。存在しないノートへのリンクとして薄く表示され、クリックすると新規作成できる）。あとでそのリンクをクリックしてテンプレートを当てはめタスク化する。
3. **タスク・プロジェクト → 添付ドキュメント**（`[[提案書.pptx]]`）
   `91_Document` に置いたPowerPoint等を、関連ノートから参照する時。
4. **（任意）作業ノート → ナレッジ記事**（例: `[[BGP設定手順]]`）
   タスクや議事録の中で、参照した手順書・設計ナレッジを指し示したい時。必須ではないが、書いておくと「このナレッジ記事がどのタスクで使われたか」をナレッジ記事側のバックリンクから逆引きできるようになる。

**逆にリンクを使わなくてよい場面:**
- メモ（`10_Inbox`・デイリーノート）は書きっぱなしでよく、他ノートへリンクする必要は無い（全文検索・タグで見つかる）
- プロジェクト／エリア側から自分に紐づくタスクへ手動でリンクを書く必要は無い。リンクは常に「タスク・議事録 → プロジェクト・エリア」の一方通行で書けばよく、逆方向はObsidianのバックリンクが自動で担う

## Obsidianの基本設定

### エディタ
- デフォルトビューを `リーディングビュー` にする
- 行番号の表示を `on` にする

### ファイルとリンク
- 内部リンクを毎回更新するを `on` にする（後述のフォルダ整理・リネームでリンク切れしないようにするため）
- 新規ノートの作成場所・新規添付ファイルの保存先・起動時に開くファイルは、後述の「セットアップ手順」内で設定する

### 外観
- 好みのテーマを設定する（`Typora-Vue`がすっきりしつつ色味がよい）
- リボンの表示は好みで（`off`にして左ペインをすっきりさせてもよい）

### 画面レイアウト
- 左ペイン: アイコンはブックマーク・ファイルエクスプローラ・検索の順にする
- 中央ペイン: デイリーノートなど日常的に見るノートはタブをピン留めする
- 右ペイン: 基本はアウトラインにして、必要に応じて切り替える

### コアプラグイン
- `デイリーノート`: 保存先フォルダとテンプレートファイルを設定する（詳細は後述の「セットアップ手順」を参照）
- `テンプレート`: テンプレートフォルダを設定する（同上）
- `ファイルの回復`: スナップショットの保存期間を短めに設定する（詳細は後述の「セットアップ手順」を参照）

## セットアップ手順

### 1. フォルダを作成する
vaultルート直下に以下を作成する。

| フォルダ | 用途 |
|---|---|
| `10_Inbox` | 未整理の受け皿。新規ノート作成のデフォルト保存先 |
| `20_Diary` | デイリーノート |
| `30_Work` | プロジェクト・エリア・タスク・議事録の置き場（`type`プロパティで区別するので、この中をどうサブフォルダで整理しても構わない） |
| `40_Knowledge` | ナレッジ・手順書・設計パターン等、長期参照する資料 |
| `50_Life` | 個人 |
| `60_Archive` | 完了・凍結したものの保管庫 |
| `90_Asset` | 添付「画像」専用 |
| `91_Document` | 添付「ドキュメント」専用（PowerPoint/Excel/PDF/Word等。手動で配置し、ノートから `[[ファイル名.pptx]]` でリンクする） |
| `92_Template` | テンプレート |

番号は10刻み（`10〜60`）で、間に将来フォルダを挿し込める余白を残している。添付・テンプレート等のシステム系フォルダは `90番台`にまとめ、それぞれ別番号にしている。


### 2. `.base` ファイルをvaultルート直下に**個別配置**する
`task-control` フォルダごとコピーしない。以下のファイルを1つずつvaultルート直下に置く。

- [ ] `タスクBase.base`
- [ ] `プロジェクトBase.base`
- [ ] `エリアBase.base`
- [ ] `議事録Base.base`
- [ ] `メモBase.base`

### 3. `92_Template` にテンプレートファイルを配置する
- [ ] `task.md` / `project.md` / `area.md` / `meeting.md` / `daily.md` / `memo.md` を `92_Template/` にコピーする（`task`〜`meeting`はそれぞれ `type: task` 等が最初から入っているので、ノート作成後に手で追記する必要は無い。`memo.md`は`type`を持たず`date`/`context`/`tags`のみ）
- [ ] `設定 → コアプラグイン → テンプレート` を有効化し、テンプレートフォルダの場所を `92_Template` に設定する
- [ ] `設定 → コアプラグイン → デイリーノート` の保存先フォルダを `20_Diary`、テンプレートファイルを `92_Template/daily.md`、日付形式を `YYYY-MM-DD` に設定する（ファイルタイトルがそのまま作成日になる）
- [ ] `設定 → ファイルとリンク → 新規ノートの作成場所` を `10_Inbox` に設定する（Task/Project/Area/Meetingは`type`プロパティ基準でBasesが集計するためどこに作られても影響しないが、`メモBase.base`だけはフォルダ基準で絞り込むため、この設定をしないと`Ctrl+N`で書いたメモが一覧に出てこなくなる）
- [ ] `設定 → ファイルとリンク → 新規添付ファイルの保存先` を `90_Asset` に設定する。
- [ ] `設定 → ファイルとリンク → Default file to open`（既定で開くファイル）を `Daily note`（デイリーノート）に設定する（コミュニティプラグイン不要。Obsidian 1.11で追加されたコア機能のオプションで、これにより起動時に自動で今日のデイリーノートが開く）

継続的な運用業務（運用・保守など、終わりが無いもの）は `project` テンプレートではなく `area` テンプレートを使う。

### 4. ショートカットキーを割り当てる
- [ ] `設定 → ホットキー` で「テンプレート: テンプレートを挿入」に任意のキー（例: `Ctrl+Shift+N`）を割り当てる（下記「テンプレート挿入のショートカットについて」参照）
- [ ]  `設定 → ホットキー` で「デイリーノート: 今日のデイリーノートを開く」に任意のキー（例: `Ctrl+D`）を割り当てる
- [ ] `設定 → ホットキー` で「ファイルを別のフォルダへ移動」に任意のキー（例: `Ctrl+M`）を割り当てる（Obsidianのコア機能。コミュニティプラグイン不要。`10_Inbox`のメモが具体化した後、対応フォルダへ移動する際に使う。詳細は「業務での使い方」を参照）
- [ ] `設定 → ホットキー` で「ペイン: 右に分割」に任意のキー（例: `Ctrl+R`）を割り当てる

#### テンプレート挿入のショートカットについて
コアの「テンプレート」プラグインには、「特定のテンプレートを1つのホットキーで直接新規ノート作成まで行う」機能は無い（できるのはTemplater・QuickAdd等のコミュニティプラグインのみで、今回は対象外）。コアだけで実現できる最速の流れは次の通り:

1. `Ctrl+N` で空ノートを作成（`10_Inbox`に保存される）
2. 割り当てたホットキー（例: `Ctrl+Shift+N`）で「テンプレートを挿入」を呼び出す
3. あいまい検索でテンプレート名（`task`/`project`/`area`/`meeting`/`memo`）を数文字打って `Enter`

テンプレートが6種類だけなので、あいまい検索の絞り込みはほぼ1〜2文字で候補が1件に絞れる。デイリーノートだけは例外で、コアの「デイリーノート」プラグイン自体に「今日のノートを開く（無ければ作成しテンプレート適用まで自動）」という単独コマンドがあるので、これにホットキーを割り当てれば1キーで完結する（`設定 → ホットキー` → 「デイリーノート: 今日のノートを開く」）。

### 5. ファイルの回復の保存期間を設定する
- [ ] `設定 → コアプラグイン → ファイルの回復` を開き、スナップショットの保存期間を既定より短い期間（例: 3日程度）に設定する（Obsidianのコア機能。コミュニティプラグイン不要）

### 6. 動作確認
- [ ] `sample-data/` のサンプル（`30_Work` 配下のProject・Area・Task・Meeting、`10_Inbox`/`20_Diary` のメモ）をコピーする
- [ ] `タスクBase.base` を開き、「タスク一覧」「期限順」「優先度別」「コンテキスト別」「チェック日順」「期限切れ・本日期限」「本日チェック」の7タブが表示されエラーが無いことを確認する
- [ ] `プロジェクトBase.base`・`エリアBase.base`・`議事録Base.base` を開き、それぞれ対応するノートが表示されることを確認する
- [ ] デイリーノートを開き、「全体管理」セクションのプロジェクト一覧・エリア一覧・最近の議事録・最近のメモの4つの埋め込みビューが全て表示されることを確認する
- [ ] 試しに1つのタスクノートを `30_Work` 内の別のサブフォルダへ移動し、`タスクBase.base` の表示件数が変わらないことを確認する（`type`プロパティ基準でフォルダに依存しないことの確認）

## 既知の制約
- `context` プロパティ（wikilink）での `groupBy` は、Obsidian側の実装により見え方が変わる可能性がある。実際に開いて意図通りグルーピングされるか確認すること
- プロジェクト/エリアごとの完了・未完了「件数」を数値で出す機能（rollup）は組み込んでいない。Bases の formula（`file.backlinks` 等）でも実現できる可能性があるが、手動リロードが必要など制約があるため見送った。必要になったら追加検討する
