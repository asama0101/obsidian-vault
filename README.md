# 秘書vault

Obsidianを「見る場所」、Claude Codeを「秘書業務を回す場所」として使う個人用vault。

## 使い方

1. 1日の最初に Claude Code に「今日のノートを開いて」等と伝える。その日のデイリーノート `6_Cabinet/Diary/<今日の日付>.md` が作られ、予定とタスクが埋まる。
2. あとはそのデイリーノートを開いておくだけでよい。30分ごとに内容が最新化される。ファイル名は日々変わるので、`6_Cabinet/Diary/` フォルダをブックマークしておくと、その日のファイルをすぐ開ける。
3. 思いついたこと・受けた依頼はデイリーノートの `## メモ` に1行で書く。次の更新でノートになり、行の後ろにリンクが付く。
4. 出席した会議は `## 今日の予定` の行にチェックを入れる。次の更新で議事録ノートが「実施済」になる。
5. `## Claudeからの連絡` の `### 確認したいこと` に質問が現れたら、`→` の右に答えを書く。次の更新で処理される。`### 連絡事項` にはAIからのお知らせが書かれるが、返信は不要。
6. メール・チャットの本文をそのまま渡したいときは、会話に貼り付ける。分類されてノートになる。
7. 1日の終わりに「締めて」（または「クリアデスクして」）と伝える。その日の変更がコミットされる。デイリーノートはそのまま `6_Cabinet/Diary/` に残り、過去分になる。

通知は飛ばない。見に行けば常に最新になっている。

「今日のノートを開いて」等と伝えたとき、次の2つの場合に何もせず止まる。どちらも自分で復旧する。

- **「前日分が締められていない」と言って止まったとき**: 締め忘れた日のノート `6_Cabinet/Diary/<その日の日付>.md` があるかどうかで手順が変わる。締めを忘れた日があると、その日のまま作業が続いてしまうため止める。
  - ノートがある場合: 先に「締めて」と伝えてから、あらためて「今日のノートを開いて」等とやり直す。
  - ノートが無い場合: 締めるべき記録が無いので締める必要はない。ターミナルで `git checkout main` を実行して `main` に戻ってから「今日のノートを開いて」等とやり直す。この状態で「締めて」と伝えても「ありません」と言われて止まる。
- **「想定外のブランチにいる」と言って止まったとき**: `main` か当日の日次ブランチ `daily/<今日の日付>` へ移ってから「今日のノートを開いて」等とやり直す。秘書ループはこの2つのブランチ以外では動かない。

## どこに何があるか

| 場所 | 用途 |
|---|---|
| `6_Cabinet/Diary/<今日の日付>.md` | 唯一の接点。予定・タスク・確認事項・メモ |
| `6_Cabinet/Diary/` の他のファイル | 過去のデイリーノート |
| `<案件名>.md`（vault直下） | 案件ノート本体。案件フォルダとは別にvault直下へフラットに置く |
| `1_Notes/<案件名>/` | 案件ごとのフォルダ（案件ノート自体は含まない）。`meeting/`・`task/`・`documents/` に議事録・タスク・資料が分かれている |
| `2_know-how/` | 再利用できる手順・知識のノート |
| `3_Inbox/` | まだ案件が決まっていない task・meeting ノート |
| `4_Archive/` | 完了した案件（`status: 2_done`）のフォルダ一式。案件ノートごとまるごと移動する |
| `5_Reference/` | 案件をまたいで使う資料。メーカー名・ベンダー名のサブフォルダに分かれている |
| `6_Cabinet/Bases/` | 一覧ビュー4本。日常では見ず、棚卸しや検索のときだけ開く |
| `6_Cabinet/MEMORY.md` | 人・状況についての長期記憶 |

`1_Notes/`・`2_know-how/`・`3_Inbox/`・`4_Archive/`・`6_Cabinet/` の中身とvault直下の案件ノートは Claude Code が管理する。手で整理する必要はない。人が書き込むのは当日のデイリーノートと、資料をドラッグ&ドロップで入れる案件フォルダの `documents/` や `5_Reference/` で、それ以外は読むだけでよい。

## ノートの4種類

`type` プロパティで区別する。`project` ノート自体はvault直下にフラット配置し、その案件配下の議事録・タスク・資料は `1_Notes/<案件名>/` の `meeting/`・`task/`・`documents/` に分かれる。案件が決まっていない `task`・`meeting` は `3_Inbox/`、`know-how` は `2_know-how/` に置く。

- `task` — 期限や完了条件がある、自分が行う具体的な行動
- `project` — 複数のタスクを束ねる、数週間以上続く案件
- `meeting` — 会議。カレンダーから自動で作られるほか、議事録を貼って作ることもできる
- `know-how` — 再利用できる手順・知識

## 資料の紐付け

資料はAIが自動で振り分けることはせず、人がドラッグ&ドロップで直接適切な場所に入れる。案件の資料なら `1_Notes/<案件名>/documents/`、案件をまたいで使う資料なら `5_Reference/` の該当サブフォルダへ置く。

会議の資料は議事録ノートの `## 資料` からリンクされる。カレンダーの添付とdescription内のURLは自動で貼られる。

## 中身を知りたいとき

- 秘書の手順: `.claude/skills/today/SKILL.md`

- 今回の再構成の設計: `.claude/specs/2026-09-07-vault-restructure-design.md`
