# today: 開始手順（旧daily）

あなたはこのObsidian vaultのデイリーノート運用を担当する。

## 手順

1. 今日の日付（`YYYY-MM-DD`形式）を確認する。
2. Gitブランチを確認する。
   - `references/branch-check.md`の手順で、今日の日次ブランチを確認・切り替え・作成する。
   - `git branch --list "daily/*"`で他日の`daily/YYYY-MM-DD`ブランチが残っていないか確認する。残っていたら、その日の締め処理（`today`スキルの`references/closing.md`）が未実行の可能性があるとしてユーザーに警告する（マージ・削除は自動では行わない。あくまで警告のみ）。
3. `20_Diary/<今日の日付>.md` が存在するか確認する。
   - **存在する場合**: 本来は新規作成が前提のため異常系として扱う。`references/update.md`をスコープ`全部`として実行し、その旨をユーザーに伝えて終了する（以下の手順は実行しない）。
   - **存在しない場合**: 手順4に進む。
4. `92_Template/daily.md` の内容をコピーし、frontmatterの`date: {{date}}` を実際の日付に置き換えて新規作成する。
   - `references/task-note.md`の検索条件で対象タスクを検索する。
   - 同ファイルの出力構造（期限超過グループ／`context`ごとのグループ化）に従って`## 今日のタスク`見出し配下に書き込む。新規作成のためチェック状態はすべて`- [ ]`とする。
5. 利用可能なカレンダーMCPツール（Google Calendar・Outlook）を確認する。
   - 使えるツールがあれば当日の予定を取得する。
   - 使えるツールが無い場合はこの手順以降の予定取得・議事録生成をスキップする（エラーにしない）。
6. 取得した予定から「会議候補」（`references/meeting/calendar-candidate.md`の基準）を抽出する。
7. **議事録ノートの生成**:
   - 会議候補が0件の場合はこの手順をスキップする。
   - 会議候補が1件以上ある場合: `references/meeting/calendar-candidate.md`の手順に従い（新規作成直後のため`## スケジュール`欄は空として渡す）、各会議候補に適用する（開始時刻順）。各候補について`ノートあり`・`不参加`のいずれかの結果を得る。
8. **スケジュール欄の自動入力**:
   - 手順5で予定が取得できた場合、取得した今日の予定のうち手順7の結果が`不参加`だったものを除いて、開始時刻順に`## スケジュール`見出し配下へ書き込む（書式は`references/meeting/calendar-candidate.md`の「スケジュール欄の書式」を参照）。
   - 会議候補への反映（`### 不参加`欄への振り分け・議事録ノートへのリンク埋め込み）は`references/meeting/calendar-candidate.md`の「呼び出し元での結果の使い方」に従う。
9. 新規作成した日次ノート、および手順7で作成した議事録ノート（あれば）のパスをユーザーに報告する。
