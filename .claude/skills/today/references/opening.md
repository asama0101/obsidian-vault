# today: 開始手順（旧daily）

あなたはこのObsidian vaultのデイリーノート運用を担当する。

## 手順

1. 今日の日付（`YYYY-MM-DD`形式）を確認する。
2. Gitブランチを確認する。
   - `git branch --list "daily/*"`で既存の日次ブランチを確認する。今日の
     日付以外の`daily/YYYY-MM-DD`ブランチが残っていたら、その日の締め処理
     （`today`スキルの`references/closing.md`）が未実行の可能性があるとして
     ユーザーに警告する（マージ・削除は自動では行わない。あくまで警告のみ）。
   - 今日の日付の`daily/<今日の日付>`ブランチが既に存在すればチェック
     アウトする。無ければ`main`から`git checkout -b daily/<今日の日付>`
     で新規作成する。
3. `20_Diary/<今日の日付>.md` が存在するか確認する。
   - 存在しない場合: `92_Template/daily.md` の内容をコピーし、frontmatterの
     `date: {{date}}` を実際の日付に置き換えて新規作成する。作成時、
     `30_Work/`配下の`type: task`ノートのうち`status`が`3_done`ではなく、
     かつ`due`が今日以前または`check`が今日以前のものを検索し、重複を
     除いて`## 今日のタスク`見出し配下に`- [ ] [[ノート名]]`形式で追記する。
     このとき、下記「タスク注記」のルールに従い期限超過の注記を付ける。
   - 存在する場合: そのまま開く（`## スケジュール`・`## 今日のタスク`・
     `## メモ`欄の既存内容は上書きしない。今日のタスクの自動入力は新規作成
     時のみ行う）。なお`## 繰り返しのタスク`欄は自動連携が無い純粋な
     手書きチェックリストで、この手順の対象外。

## 手順4-8（新規作成した場合のみ実行するブロック）

手順3で新規作成した場合のみ、以下の手順4〜8を実行する。既存ノートを
開いた場合（手順3で「存在する場合」だった場合）はこのブロック全体を
スキップする（カレンダーAPIも呼び出さない）。予定の再取り込みが必要で
あれば`references/check-in.md`（途中確認）の実行をユーザーに案内する。

4. 利用可能なカレンダーMCPツール（Google Calendar・Outlook）を確認する。
   - 使えるツールがあれば当日の予定を取得する。
   - 使えるツールが無い場合はこの手順以降の予定取得・議事録生成をスキップ
     する（エラーにしない）。
5. 取得した予定のうち、参加者が2名以上、かつ終日予定でないものを
   「会議候補」とする。
6. **議事録ノートの生成**: 手順5で「会議候補」が1件以上あれば、
   `.claude/skills/today/references/meeting.md`をReadし、その手順を各会議
   候補に適用する（開始時刻順）。各候補について`作成`・`既存`・`不要`・
   `保留`のいずれかの結果を得る。会議候補が0件ならこの手順はスキップする。
7. **スケジュール欄の自動入力**: 手順4で予定が取得できた場合、取得した今日の
   予定全てを開始時刻順に`## スケジュール`見出し配下へ
   `- HH:MM-HH:MM 予定タイトル`形式で書き込む。会議候補のうち手順6の結果が
   `作成`・`既存`だったものは末尾に` → [[議事録ノート名]]`を、`不要`・`保留`
   だったものは末尾に` (議事録不要)`を付ける。終日予定は`- (終日) 予定タイトル`
   とする。
8. **議事録欄の自動入力**: 手順6の結果が`作成`・`既存`だった議事録ノートへの
   リンクを`## 議事録`見出し配下に`- [[議事録ノート名]]`形式で列挙する
   （該当が無ければ空欄のままにする）。

## 手順9-10（毎回実行）

9. **今日作成・更新したノート一覧の再生成（毎回）**: vaultルートで
   `git status --short -- 30_Work 40_Knowledge 10_Inbox`を実行する
   （日次ブランチは日中コミットしないため、git statusの結果がそのまま
   「今日作成・更新したノート」の正確な集合になる）。ステータスが`??`
   （未追跡）のパスは「作成」、`M`等の追跡済みファイルへの変更は「更新」
   として分類する。`D`（削除）と`??`（未追跡）のペアで同じファイル名を
   持つものは、フォルダ移動によるものとみなし「更新」として扱う（新規
   作成ではない）。デイリーノート自身（`20_Diary/`配下）は対象外。該当
   ノートをtypeごとにグルーピングし、`- [[ノート名]]（作成）`または
   `- [[ノート名]]（更新）`形式でリストを作る。`## 今日作成・更新した
   ノート`見出し配下の内容を、このリストで置き換える（新規作成・既存
   ノートを開く場合の両方で毎回実行し、常に最新化する）。
10. 作成・更新したファイルのパス一覧をユーザーに報告する。

## タスク注記

手順3で「今日のタスク」を自動反映する際、`due`/`check`の期限超過を
`- [ ] [[ノート名]]**（due YYYY-MM-DD超過）**`の形式で注記する。検索条件
（`due`が今日以前 または `check`が今日以前）と揃え、以下の優先順位で
1つだけ注記する。

1. `due`が設定されており今日以前 → `**（due YYYY-MM-DD超過）**`。ただし
   `due`が今日と同日なら「超過」を付けず `（due YYYY-MM-DD）`とする。
2. 上記に該当せず`check`が設定されており今日以前 → `**（check YYYY-MM-DD超過）**`。
   同様に`check`が今日と同日なら「超過」を付けない。
