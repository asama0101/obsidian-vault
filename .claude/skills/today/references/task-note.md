# today: タスク検索・出力ルール

`## 今日のタスク`欄の対象タスク検索条件、基準日の分類、および出力フォーマット。`opening.md`・`update.md`・`closing.md`から共通で参照される。

## 入力

なし（検索条件は固定）。

## 検索条件

`30_Work/`配下の`type: task`ノートのうち、`status`が`4_done`・`5_cancelled`のいずれでもなく、かつ`due`が今日以前または`check`が今日以前のもの。

## 分類

各対象タスクの基準日を、検索条件と同じ優先順位で決定する（このいずれかには必ず該当する）。

1. `due`が設定されており今日以前の場合 → `due`を基準日とする
2. 上記に該当せず、`check`が設定されており今日以前の場合 → `check`を基準日とする

基準日を用いて以下に分類する。

- 基準日が今日より前 → 「期限超過」グループ
- 基準日が今日と同日 → 通常グループ（`context`ごとにグループ化。詳細は下記）

## 注記形式

`- [ ] [[ノート名]]（due YYYY-MM-DD）` または `- [ ] [[ノート名]]（check YYYY-MM-DD）`。
太字強調や「超過」の文言は付けない（期限超過は見出しで表現するため）。

## 出力構造

```
### 期限超過
- [ ] [[ノート名]]（...）

### [[プロジェクト名]]
- [ ] [[ノート名]]（...）

### 未分類
- [ ] [[ノート名]]（...）
```

- **期限超過**: 該当タスクを`context`に関係なく単一リストにする。並び順は基準日が古い（超過日数が大きい）順。同日の場合はプロジェクト名の文字列順（`context`空欄は末尾）でタイブレークする。該当タスクが無ければこの見出し自体を省略する。
- **通常グループ**: タスクの`context`プロパティ（プロジェクトノートへの`[[...]]`リンク）ごとに`### [[プロジェクト名]]`見出しでグループ化する。
  - 基準日は分類上すべて「今日」で揃うため、並び順の基準にはしない。
  - グループの並び順: プロジェクト名の文字列順。
  - グループ内タスクの並び順: ノート名の文字列順。
  - `context`が空欄のタスクは「未分類」という固定名の見出しにまとめ、常に最後に配置する。
  - 通常グループも該当タスクが無ければ見出しごと省略する。

## 出力

上記の出力構造に従ってフォーマット済みの`## 今日のタスク`本文（見出し＋`- [ ] [[ノート名]]（...）`形式の行）。チェック状態（`[ ]`/`[x]`）の決定は呼び出し元（`opening.md`・`update.md`）の責務とする。
