# meeting: 議事録ノートの新規作成

あなたはこのObsidian vaultの議事録ノート作成を担当する。以下の処理を実行する：
- テンプレートは`92_Template/meeting.md`の1本のみを使う。
- 「定例か否か」は判定しない。
- 代わりに同じプロジェクトの直近の議事録を探す。
- 前回議事録があれば、未完了のアクションアイテムと次回の議題を引き継ぐ。

`.claude/skills/today/references/meeting/calendar-candidate.md`から呼び出される。プロジェクト名の確認・重複判定（`calendar_event_id`のLookup A）は呼び出し元が既に済ませているため、このファイルは呼び出し元から渡された入力をそのまま使い、自前での解決・再確認は行わない。

## 入力

- `context`: プロジェクトのwikilink、または「該当なし」
- タイトル・URL・出席者一覧・開始時刻・終了時刻・description
- `calendar_event_id`（あれば）
- `calendar_series_id`（定例会議の場合のみ、あれば）

## 手順

1. **プロジェクト名の特定**: 入力の`context`をそのまま使う。
2. 前回議事録の検索と未完了アクションアイテムの収集:
   - `context`が定まっている場合、同じ`context`を持つ既存の議事録ノート（`type: meeting`）を`30_Work/`配下から検索し、`date`が最も新しいものを1件特定する。
   - `context`が空欄（「該当なし」）で、かつ`calendar_series_id`が定まっている場合は、代わりに同じ`calendar_series_id`を持つ既存の議事録ノートを`30_Work/`配下から検索し、`date`が最も新しいものを1件特定する。
   - `calendar_series_id`も定まっていなければこの手順は空振りでよい。
   - 見つかった場合、そのノートの`## アクションアイテム`見出し配下の未チェック項目（`- [ ] [[ノート名]]`）のうち、ノート名が空（`[[]]`）でないものを収集する（手順5で使う）。
   - **次回の議題の収集**:
     - `calendar_series_id`が定まっている（定例会議の）場合、上記とは別に、同じ`calendar_series_id`を持つ既存の議事録ノートを`30_Work/`配下から検索し、`date`が最も新しいものを1件特定する。
     - （同じプロジェクトに複数の定例シリーズが存在しうるため、「次回の議題」は`context`一致検索ではなく必ずこのシリーズ一致検索から取得する）
     - 見つかった場合、そのノートの`## 次回`見出し配下の「議題」行（`- 議題: ...`）の内容を収集する（手順7で使う）。
     - `calendar_series_id`が定まっていない場合、この項目は空振りでよい。
3. **ファイル名の決定**:
   - `calendar_event_id`が定まっている場合:
     - ファイル名は`<今日の日付>_<プロジェクト名>_<予定タイトル>.md`とする（`context`が「該当なし」の場合は`<今日の日付>_<予定タイトル>.md`）。
     - 予定タイトルはファイルシステムで使用できない文字（`/ \ : * ? " < > |`等）を除去または`_`に置換する。
     - 生成したファイルパスが偶然既に存在する場合は末尾に`_2`・`_3`...と連番を付与して回避する。
   - `calendar_event_id`が定まっていない場合:
     - ファイル名は`<今日の日付>_<プロジェクト名>.md`とする。
     - 既に同じファイルパスのノートが存在する場合は、新規作成せずスキップする（人間が書き足した既存の議事録内容を無警告で上書きしないため）。その旨と既存ファイルパスをユーザーに報告し、以降の手順は行わない。
   - いずれの場合も、決定したファイル名で`30_Work/`直下に作成する。
4. frontmatterの初期化:
   - `92_Template/meeting.md`を使う。
   - frontmatterの`date`を今日の日付で埋める。
   - `context`を入力の値で埋める。
   - `calendar_event_id`・`calendar_series_id`が定まっている場合はそれぞれのfrontmatterに書き込む。定まっていなければ空欄のままにする。
5. **前回のアクションアイテムの記載**:
   - 手順2で収集したアクションアイテムがあれば、`## 前回のアクションアイテム`見出し配下に列挙する。
   - `calendar_series_id`が定まっている（定例会議の）場合:
     - 項目ごとに対応する`ノート名`のファイルが`type: task`のノートとしてvault全体（`30_Work/`配下に限らず`10_Inbox/`等も含む）に既に存在するか確認する。
     - 存在すれば`- [[ノート名]]（タスク化済み・status: <取得したstatus値>）`形式で記載する（タスク自体がstatusで進捗を管理するため、チェックボックスは付けない）。
     - 存在しなければ`- [ ] [[ノート名]]`形式で記載する。
   - `calendar_series_id`が定まっていない場合（定例でない場合）は、既存タスクの有無を確認せず、収集した全項目をそのまま`- [ ] [[ノート名]]`形式で列挙する。
   - 収集した項目が無ければ空欄のままにする。
6. **会議情報の記載**:
   - 入力のタイトル・URL（ビデオ会議リンクがあればそれ、無ければカレンダーイベント自体のURL）・出席者（参加者一覧）・開始時刻・終了時刻が定まっている場合:
     - `## 会議情報`見出し配下の該当する項目（タイトル・URL・開始時刻・終了時刻）にそれぞれ記載する。
     - 出席者は`## 出席者`見出し配下に箇条書きで記載する。
   - 定まっていない場合は該当欄を空欄のままにする。
   - `## 資料`欄は自動入力しない（常に空欄のまま、手動運用）。
7. **議題欄の初期値**: `## 議題`見出し配下の初期値を、以下の優先順位で決定する。
   1. `calendar_series_id`が定まっている（定例会議の）場合: 手順2で取得した前回議事録の`## 次回`欄「議題」行に記載があれば、それをそのまま転記する。
   2. 上記に該当しない場合（定例でない・前回議事録が無い・前回の議題欄が空、のいずれか）:
      - 入力のdescriptionが定まっていれば、その内容を候補とする。
      - descriptionが議題として意味を成す本文を含まない場合（URL・リンクのみ、または「Microsoft Teams 会議」「会議に参加するにはここをクリック」等の参加用定型文・電話番号・会議ID等の招待ボイラープレートのみで構成される場合）は自動転記せず、`AskUserQuestion`で「この予定の説明欄に議題として使えそうな記載が見当たりません。## 議題欄の初期値はどうしますか？」を確認する。選択肢: `そのまま議題欄に転記する` / `空欄のままにする`。
      - 議題として意味を成す本文が含まれていればそのまま転記する。
   3. いずれにも該当しない場合は空欄のままにする。
8. 作成したファイルパスをユーザーに報告する。

## 出力

作成したファイルパス、またはスキップ理由（既存ファイルパス）。
