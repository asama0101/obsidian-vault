# 今日のタスク

タスク索引から `## 今日のタスク` に載せる対象を絞り込み、チェックリストとして描画する手順と、チェック・→メモの書き戻しロジックを扱う。`## 今日の予定` における `references/calendar.md` と同じ役割を持つ正典。

## 対象の絞り込み

1. `index.py --type task` を1回だけ叩く。**個別ノートを1件ずつ読んではならない。** 既定で `status` が `4_done`・`5_cancelled` の task は落ちるため、この出力に含まれる行はすべて未完了タスクである。
2. 該当行のうち、`due` が空でなく `due <= 今日`（期限切れを含む）、または `date == 今日` のものだけを対象にする。
3. 並び順は `due` 昇順→`title` 昇順とする。
4. `### 今日やること` 見出しと直後の `![[タスク.base#今日やること]]` は該当0件でも常に出す。省略するのはチェックリスト行だけで、該当が0件の日はチェックリスト行を1行も出さない。

## 描画書式

```
## 今日のタスク

### 今日やること

- [ ] [[<タスクノート名>]]（<メタ情報>） →

![[タスク.base#今日やること]]
```

- `<タスクノート名>` は `title` 列（拡張子無し）をそのまま使う。
- `<メタ情報>` は `project`（空でなければそのまま。例 `[[大手町DC コアSW更改]]`）と `期限:<due>`（`due` が空なら代わりに `予定日:<date>`）を `・` で連結する。両方無ければ丸括弧ごと省略し `- [ ] [[<タスクノート名>]] →` とする。
- 末尾の ` →` はどの行にも必ず付ける（進捗メモの書き込み先のため）。
- `![[タスク.base#今日やること]]` は固定文字列で、全置換のたびに書き直すが内容は変わらない（status・due・blocked_by等の詳細カラムをObsidian側で一覧できるようにするための参照用表示であり、AIが値を計算する対象ではない）。該当0件でチェックリスト行を省略する日も、`### 今日やること` 見出しとこの行は残す。

## チェック・→メモの書き戻し（更新モード・締めモードで実行）

現在の `## 今日のタスク` のチェックリストの各行を読み、次の順で処理する。1行がチェック済みかつ`→`にもテキストがある場合は **(a) を先に行ってから (b) を行う**（進捗メモの追記を先に、完了処理を後に。逆順にすると `1_todo→2_doing` の昇格が完了済みタスクに対して無意味に発生するため）。

- **(a) `→` の右にテキストがある行**: 対応するタスクノートの本文 `## 進捗メモ` 見出し配下の末尾に `- <今日の日付>: <→の右のテキスト>` を追記する。追記後、そのタスクノートの現在の `status` が `1_todo` であれば `2_doing` に変更する（`2_doing` 以降なら変更しない）。
- **(b) チェック済み（`- [x]`）の行**: 対応するタスクノートの frontmatter を `status: 4_done`・`done: <今日の日付>` に更新する。

対象ノートの特定は行内の `[[タスクノート名]]` リンクをそのまま使う（あいまい一致は行わない。1行につきタスクは1件）。

この処理の後に続く全置換再生成（`update.md` の「日次ノート再生成」節参照）で表示を確定させる。完了させたタスクは次に叩く `index.py --type task` の出力から既定除外され、再生成後のチェックリストに自動的に現れなくなる（`## 今日の予定` の出席処理と同じ冪等パターン）。**チェックリストの行自体には処理済みマーカーを付けない**（全置換再生成が正であるため不要）。

締めモードでも保留中（未処理のチェック・→メモ）があれば同じ (a)(b) の手順を適用する。ただし締めでは表示の全置換再生成は不要（ノート側の状態を確定させるだけでよい。デイリーノートは他の締め手順とまとめて1コミットになる）。
