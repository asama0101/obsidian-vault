# today: 会議候補ごとの議事録処理

`references/opening.md`・`references/schedule-sync.md`から、当日の「会議候補」
（参加者2名以上・終日でない予定）の一覧が定まった時点で呼び出される。この
ファイルの手順を会議候補ごとに（開始時刻順に）適用し、各候補について以下の
いずれかの結果を呼び出し元へ返す。

- `作成`: 議事録ノートを新規作成した。ノート名を含む。
- `既存`: 対応する議事録ノートが既に存在した（再質問なし）。ノート名を含む。
- `不要`: 過去に「議事録不要」と回答済みだった（再質問なし）。
- `保留`: 今回はじめて確認し、ユーザーが「議事録不要」を選んだ（今回のみ）。

呼び出し元はこの結果を使って`## スケジュール`欄・`## 議事録`欄を組み立てる
（本ファイルはデイリーノートへの書き込みを行わない）。

## 手順（会議候補1件につき）

1. **既存ノートの確認（再質問回避・優先）**: 今日該当する`type: meeting`
   ノートのうち、frontmatterの`calendar_event_id`がこの予定の`id`と一致する
   ものが`30_Work/`配下に存在するか検索する。存在すれば、Q1・Q2を確認せず
   結果を`既存`（ノート名付き）として次の会議候補へ進む。
2. **「議事録不要」の確認（再質問回避）**: 手順1で見つからなかった場合、
   デイリーノートの現在の`## スケジュール`欄に、この予定と**タイトルが一致**
   する既存行があり、かつその行に`(議事録不要)`という印が付いているか確認
   する。付いていれば、Q1を確認せず結果を`不要`として次の会議候補へ進む。
3. **プロジェクトの自動マッチ試行**: この予定のタイトル・説明・場所を結合した
   テキストに対し、`30_Work/`配下の`type: project`ノートの`file.name`が部分
   文字列として含まれるか照合する。1件だけ一致すればその項目を「自動マッチ
   候補」として記録する（0件・複数件の場合は自動マッチ候補なしとして扱う）。
4. **Q1（毎回確認）**: 「予定『&lt;タイトル&gt;』(&lt;開始時刻&gt;-&lt;終了時刻&gt;)
   の議事録を作成しますか？」を`AskUserQuestion`で確認する。
   選択肢: `作成する` / `議事録不要（参加しない等）`
   - 「議事録不要」を選んだ場合: 結果を`保留`として次の会議候補へ進む
     （呼び出し元がスケジュール行に`(議事録不要)`を付ける）。
5. **Q2（自動マッチが定まらなかった場合のみ）**: 手順3で自動マッチ候補が1件
   に定まらなかった場合、「どのプロジェクトですか？」を`AskUserQuestion`で
   確認する。選択肢は手順3で見つかった候補（複数件ヒットした場合はそれら）
   ＋`該当なし`とし、「その他」欄でのプロジェクト名の直接入力も許可する。
   自動マッチが1件に定まっていた場合はこの手順を省略し、その候補をそのまま
   `context`として採用する。
6. **議事録ノートの生成**: `.claude/skills/meeting/SKILL.md`の手順に従い、
   以下を渡してノートを生成する。
   - `context`: 手順4/5で定まったプロジェクトのwikilink、または「該当なし」
   - タイトル: この予定のタイトル
   - URL: ビデオ会議リンク（あれば）、無ければカレンダーイベント自体のURL
   - `calendar_event_id`: この予定の`id`
   - `calendar_series_id`: この予定の`recurringEventId`（Outlook/Teamsの場合は
     `seriesMasterId`）。単発予定の場合は渡さない（空欄のままにする）。
   結果を`作成`（生成したノート名付き）として次の会議候補へ進む。

## 呼び出し元での結果の使い方

- `作成`・`既存`: `## スケジュール`欄の該当行末尾に` → [[ノート名]]`を付与し、
  `## 議事録`欄にそのノート名へのリンクを列挙する。
- `不要`・`保留`: `## スケジュール`欄の該当行末尾に` (議事録不要)`を付与する。
  `## 議事録`欄には載せない。
