# today: 途中確認手順（旧schedule-sync）

あなたはこのObsidian vaultのデイリーノートを、カレンダー・今日のタスク・
今日作成/更新したノートの最新状態に同期する「途中確認」処理を担当する。
開始処理（`references/opening.md`）実行後、日中いつでも単独で呼び出される。
1日に何度呼び出しても安全（既存議事録ノートは再質問せず、削除は必ず確認を
挟む）。

## 手順0: スコープ判定

ユーザー発言から更新範囲（スコープ）を判定する。

1. 発言に含まれるキーワードで判定する。
   - 「予定」「スケジュール」「カレンダー」を含む → **カレンダーのみ**
     （「〜だけ」「〜のみ」等の修飾語の有無を問わない。例:
     「スケジュール更新して」「予定変わったから反映して」
     「予定を再取得して」はすべてこれに該当する）
   - 「タスク」を含む → **タスクのみ**
   - 「ノート」を含む → **ノートのみ**
   - 「全部」「すべて」「まとめて」等を含む → **全部**
   - 上記のいずれにも該当しない、または複数カテゴリのキーワードに同時に
     該当する場合 → `AskUserQuestion`で「更新範囲はどれですか？」を確認する。
     選択肢: `カレンダーのみ` / `タスクのみ` / `ノートのみ` / `全部`。
2. 判定結果を`スコープ`として、以降の手順4-13.5の実行可否に使う。

## 前提確認

1. 今日の日付（`YYYY-MM-DD`形式）を確認する。
2. `20_Diary/<今日の日付>.md`が存在するか確認する。
   - 存在しない場合: 開始処理（`references/opening.md`）が未実行なので、その旨を
     ユーザーに伝えて中断する（このファイル自体は作成しない）。
   - 存在する場合: 手順3へ進む。
3. Gitブランチを確認する。今日の日付の`daily/<今日の日付>`ブランチが既に
   存在すればチェックアウトする。無ければ`main`から
   `git checkout -b daily/<今日の日付>`で新規作成する（前提確認手順2で当日
   ノートが既に存在することを確認済み＝`references/opening.md`が実行済みの
   可能性が高いため、他日の`daily/*`ブランチ残存に対するstale-branch警告は
   ここでは行わない）。

## 手順（カレンダー再同期: スコープが`カレンダーのみ`または`全部`の場合のみ実行）

4. 利用可能なカレンダーMCPツール（Google Calendar・Outlook）を確認する。
   - 使えるツールが無い場合はユーザーにその旨を伝え、このカレンダー再同期
     ブロック（手順4-10）をスキップする（エラーにしない）。スコープが
     `全部`の場合は、続けて手順11以降（タスク再計算・ノート一覧再生成・
     状態サマリー）を実行する。
5. 当日の最新の予定を取得する。取得した予定のうち、参加者が2名以上、かつ終日
   予定でないものを「会議候補」とする（`opening.md`と同一基準）。
6. **会議候補の処理**: 手順5で「会議候補」が1件以上あれば、
   `.claude/skills/today/references/meeting.md`をReadし、その手順を各会議
   候補に適用する（開始時刻順）。各候補について`作成`・`既存`・`不要`・
   `保留`のいずれかの結果を得る。会議候補が0件ならこの手順はスキップする。
7. **`## スケジュール`欄の全件洗い替え**: 取得した今日の予定全てを開始時刻順に
   `## スケジュール`見出し配下へ`- HH:MM-HH:MM 予定タイトル`形式で書き込み、
   既存の内容を置き換える。会議候補のうち手順6の結果が`作成`・`既存`だった
   ものは末尾に` → [[議事録ノート名]]`を、`不要`・`保留`だったものは末尾に
   ` (議事録不要)`を付ける。終日予定は`- (終日) 予定タイトル`とする。
8. **議事録の削除候補の検出**: `20_Diary/<今日の日付>.md`の`## 議事録`見出し
   配下にある既存リンク（`- [[議事録ノート名]]`）それぞれについて、リンク先
   ノートのfrontmatterから`calendar_event_id`を読み取る。手順5で取得した今回の
   会議候補一覧の中に、同じ`calendar_event_id`を持つ予定が存在しなければ、その
   ノートを「削除候補」とする（予定が無くなった場合・会議候補の条件を満たさ
   なくなった場合の両方をこれで検出できる）。`calendar_event_id`が空欄の
   ノート（手動作成分）は削除候補の対象外とする。
9. **削除候補の確認・実行**: 削除候補が1件以上あれば、各ノートについて本文が
   テンプレートのまま（`## 議題`等の見出し配下が空欄）か、何らかの追記がある
   かを一言添えた一覧をユーザーに提示し、削除してよいか確認する。
   - 承認されたノートのみ、Obsidian vaultから削除し、`## 議事録`欄から対応する
     リンクを除去する。
   - 承認されなかった・確認できなかったノートは、ノート本体・`## 議事録`欄の
     リンクの両方をそのまま残す。
   - 削除候補が無ければこの手順はスキップする。
10. **`## 議事録`欄の更新**: 手順6の結果が`作成`・`既存`だった議事録ノートへの
    リンクと、手順9で削除されずに残った既存リンクを合わせて`## 議事録`見出し
    配下に列挙する（重複除去）。

## 手順（タスク再計算: スコープが`タスクのみ`または`全部`の場合のみ実行）

11. **`## 今日のタスク`欄の再計算**: 既存の`## 今日のタスク`見出し配下を、
    以下の手順で書き換える。
    1. 既存の各行を`- [x]`（チェック済み）と`- [ ]`（未チェック）に分類する。
    2. チェック済み行はテキストをそのまま保持し、リンク先ノート名を「保持済み
       ノート名リスト」として記録する。
    3. 未チェック行は一旦すべて破棄する。
    4. `30_Work/`配下の`type: task`ノートのうち、`status`が`3_done`ではなく、
       かつ`due`が今日以前または`check`が今日以前のものを再検索する
       （`opening.md`手順3と同じ条件）。
    5. 検索結果から、2.の「保持済みノート名リスト」に含まれるノートを除外する。
    6. 残ったノートそれぞれに、下記「タスク注記」のルールに従い注記付き
       `- [ ] [[ノート名]]（...）`行を生成する。
    7. 「チェック済み行」＋「新規生成した未チェック行」を結合し、
       `## 今日のタスク`見出し配下をこの内容で置き換える。

## 手順（ノート一覧再生成: スコープが`ノートのみ`または`全部`の場合のみ実行）

12. **`## 今日作成・更新したノート`欄の再生成**: vaultルートで
    `git status --short -- 30_Work 40_Knowledge 10_Inbox`を実行し、
    `opening.md`手順9と同じルール（`??`＝作成、`M`等＝更新、同名の
    `D`+`??`ペアはフォルダ移動として「更新」扱い）でtypeごとに
    グルーピングした`- [[ノート名]]（作成）`/`- [[ノート名]]（更新）`
    のリストを作る。`## 今日作成・更新したノート`見出し配下の内容を、
    このリストで置き換える。

## 手順（常時）

13. `## 繰り返しのタスク`・`## メモ`欄は対象外（手動管理のまま変更しない）。

## 手順13.5: 状態サマリーの算出（スコープが`全部`の場合のみ実行）

以下の4項目を算出する。デイリーノート本文には書き込まず、手順14の報告で
チャット上に提示するのみに使う。

1. **タスク進捗**: 手順11で確定した`## 今日のタスク`欄から、チェック済み
   件数／未チェック件数をカウントする。
2. **期限超過タスク**: 未チェック行のうち`**（due YYYY-MM-DD超過）**`または
   `**（check YYYY-MM-DD超過）**`注記付きの項目を抽出する。
3. **未処理の議事録候補**: 手順6の会議候補処理結果が`保留`だったもの
   （今回「議事録不要」を選んだ予定）の一覧。
4. **今日作成・更新したノート件数**: 手順12で再生成した
   `## 今日作成・更新したノート`欄のリストをtypeごとに集計する。

14. 変更点をユーザーに報告する（下記「報告」参照）。

## タスク注記

`opening.md`と同一ルール。1つだけ注記する。

1. `due`が設定されており今日以前 → `**（due YYYY-MM-DD超過）**`。ただし`due`が
   今日と同日なら「超過」を付けず`（due YYYY-MM-DD）`とする。
2. 上記に該当せず`check`が設定されており今日以前 → `**（check YYYY-MM-DD超過）**`。
   同様に`check`が今日と同日なら「超過」を付けない。

## 報告

実際に実行したスコープの内容のみをユーザーに報告する（実行しなかった
カテゴリの項目は報告に含めない）。

- スコープが`カレンダーのみ`または`全部`の場合:
  - スケジュール欄の変更点（追加・削除・時刻変更された予定）
  - 新規生成した議事録ノート件数・対象ノート名（無ければ「該当なし」）
  - 削除候補として提示したノート件数・対象ノート名、承認結果（削除した/残した）
- スコープが`タスクのみ`または`全部`の場合:
  - `## 今日のタスク`欄で新規追加・除外された項目（チェック済み項目は変更なしの旨）
- スコープが`ノートのみ`または`全部`の場合:
  - `## 今日作成・更新したノート`欄の更新有無
- スコープが`全部`の場合のみ、追加で:
  - 状態サマリー（手順13.5で算出した4項目）
