# デイリーノートの行書式

更新モードは `## 今日の予定` と `## 今日のタスク` を毎回全置換で再生成するため、書式を固定しないと出力が日々揺れる。

- `## 今日の予定`: 見出し直下、箇条書きより前に `（取得元: ...）` の1行を置く。続く行は `HH:MM-HH:MM [[議事録ノート名]]` で、載る行は必ず対応する議事録ノートを持ち、行が存在しない場合はない。チェックボックスは対応する議事録ノートの `status` に従って2値を取り、`2_実施済` なら `- [x]`、それ以外（`1_予定` 等）なら `- [ ]` とする。チェックは出席の合図として扱い、更新モードが対応する議事録ノートの `status` を `2_実施済` にする。
- `## 今日のタスク`: `- [ ] [[タスクノート名]] <状態>`。`<状態>` は `期限 今日` / `期限超過 N日` / `進行中` のいずれか。ここだけはチェックボックスを使う。人間がチェックした行を更新モードが完了の合図として読むため。
- `## Claudeからの連絡`: 2つのサブ見出しを持つ。
  - `### 確認したいこと`: `- [ ] <質問>（N回目） →`。AIは未チェックで質問行を追加する。回答済み行は削除せず、チェック済み（`- [x]`）にして保持する。`classification.md`の「確信が持てないとき」が書く。
  - `### 連絡事項`: AI発の一方向お知らせを書く。`- ⚠ `（警告。締めの未処理棚卸し・締め確認未回答の反映報告が書く）、`- ⓘ `（情報。今日新規に作った `tags` の棚卸しが書く）、`- 前日の未処理: `（繰越。開始モードが書く）の3種。人間は読むだけで、処理対象にしない。
- `## メモ`: 人間の自由記述。捕捉してノート化した行は元の文言の後ろに ` → [[ノート名]]` を足す。既存ノートへの操作指示として直接実行した行は ` → 実行済み（<何をしたか>）` を足す。

## 処理済みマーカーの判定規約

**この節がAI/人間の行判定に関する正典である。** `.claude/CLAUDE.md` と設計書はここを参照する。

`### 連絡事項` の行はすべてAI発であり、処理対象にしない。未処理件数にも数えない。人間の依頼ではなく、AIが自分の都合で書いた行のため。

`## メモ` の行はすべて人間が書いた行として扱う。**行内に `→ [[...]]` または `→ 実行済み` を含むものが処理済み、含まないものが未処理**と判定する。

**今後AIが `### 連絡事項` に新しい種類の行を書く必要が生じた場合は、必ず `⚠`/`ⓘ`/`前日の未処理:` のいずれかの接頭辞を使う。新しい接頭辞を増やさない。** 接頭辞を1つずつ列挙して判定する方式は、新しい行の種類が増えるたびに見落としを繰り返す（実際に3回発生した）。
