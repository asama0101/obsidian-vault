# デイリーノートの行書式

更新モードは `## 今日の予定` と `## 今日のタスク` を毎回全置換で再生成するため、書式を固定しないと出力が日々揺れる。

- `## 今日の予定`: 見出し直下、箇条書きより前に `（取得元: ...）` の1行を置く。続く行は `HH:MM-HH:MM [[議事録ノート名]]` で、載る行は必ず対応する議事録ノートを持ち、行が存在しない場合はない。チェックボックスは対応する議事録ノートの `status` に従って2値を取り、`2_実施済` なら `- [x]`、それ以外（`1_予定` 等）なら `- [ ]` とする。チェックは出席の合図として扱い、更新モードが対応する議事録ノートの `status` を `2_実施済` にする。
- `## 今日のタスク`: `- [ ] [[タスクノート名]] <状態>`。`<状態>` は `期限 今日` / `期限超過 N日` / `進行中` のいずれか。ここだけはチェックボックスを使う。人間がチェックした行を更新モードが完了の合図として読むため。
- `## 確認したいこと`: `- [ ] <質問>（N回目） →`。AIは未チェックで質問行を追加する。回答済み行は削除せず、チェック済み（`- [x]`）にして保持する。
- `## メモ`: 人間の自由記述。捕捉してノート化した行は元の文言の後ろに ` → [[ノート名]]` を足す。既存ノートへの操作指示として直接実行した行は ` → 実行済み（<何をしたか>）` を足す。

## 処理済みマーカーの判定規約

**この節がAI/人間の行判定に関する正典である。** `.claude/CLAUDE.md` と設計書はここを参照する。

`## メモ` の行には、**AIが書いた行**と**人間が書いた行**の2種類がある。

- AIが `## メモ` に書く行は、必ず次のいずれかの接頭辞を持つ: `- ⚠ `（警告。締めの未処理棚卸しが書く）、`- ⓘ `（情報。今日新規に作った `tags` の棚卸しが書く）、`- 前日の未処理: `（繰越。開始モードが書く）。
- **これらの接頭辞で始まる行は、処理対象にしない。未処理件数にも数えない。** 人間の依頼ではなく、AIが自分の都合で書いた行のため。
- 人間が書いた行は、**行内に `→ [[...]]` または `→ 実行済み` を含むものが処理済み、含まないものが未処理**と判定する。
- **今後AIが `## メモ` に新しい種類の行を書く必要が生じた場合は、必ず上記の接頭辞のいずれかを使う。新しい接頭辞を増やさない。** 接頭辞を1つずつ列挙して判定する方式は、新しい行の種類が増えるたびに見落としを繰り返す（実際に3回発生した）。判定規約そのものを「AI行は接頭辞で判別、人間行は `→` マーカーで判別」という2分法に一般化することで、新種の行が増えても判定規約を変えずに済むようにする。
