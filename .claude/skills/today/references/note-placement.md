# ノートの初期配置

project ノートは `new_note.py --type project` で作ると、自動的に vault直下に `<案件名>.md` として作られる（フォルダの中には入れない）。日付プレフィックスは付かない。同時に `1_Notes/<案件名>/` フォルダが作られ、以後の議事録・タスク・資料はこのフォルダの配下に集約する。

案件フォルダの構成は次のとおり。project ノート自身は含めない。

```
1_Notes/<案件名>/
├── meeting/         ← 議事録ノート
├── task/            ← タスクノート
└── documents/       ← 案件固有の資料
```

project ノート自身は `vault/<案件名>.md` にフラット配置される（案件がアクティブな間）。`status` が `2_done` になった案件は、`1_Notes/<案件名>/` フォルダと `<案件名>.md` をまとめて `4_Archive/<案件名>/<案件名>.md` へ移動する（`references/close.md` 参照）。Archive では project ノートもフォルダの中に含まれる点が `1_Notes/` との違い。

task・meeting ノートを既存の案件フォルダに置く場合は、`--project` に渡す前に**先に正確なフォルダ名を確認する**。`ls 1_Notes/` または `index.py` が返す既存ノートの `path` 列で確認し、その文字列をそのまま `--project` に渡す。`new_note.py` 側にあいまい一致や自動検索は無いため、案件名を間違えると別の新規フォルダが作られてしまう。

案件が確定していなければ `--project` を付けず、ノートの `type` に応じて次の場所に作る。

| きっかけ | 案件の確定度 | 初期の置き場所 |
|---|---|---|
| カレンダーから議事録を作る | 会議名から判定できることが多い | 案件フォルダの `meeting/`（部分一致が複数/0件のときは `3_Inbox/` に作り `### 確認したいこと` で確認する。判定ロジックの正典は `start.md` ステップ6） |
| `## メモ` から起票したタスク | 内容から判定できることもある | 案件フォルダの `task/`（部分一致が複数/0件のときは `3_Inbox/` に作り `### 確認したいこと` で確認。判定ロジックの正典は `update.md` ステップ9） |
| 障害の発生 | project がまだ存在しない | project を作ってからその配下の `task/` |
| know-how | そもそも案件を持たない | 常に `2_know-how/` |

- フォルダ名の案件名部分は project ノート名と一致させる（日付プレフィックスは無い）。
- 案件フォルダに置くノートには `--set 'project="[[案件名]]"'` も併せて渡す。フォルダは置き場所、`project` プロパティは正典であり、`プロジェクト.base` の関連ノートビューはプロパティ側を見て動く。
- 複数案件にまたがる会議は、実体を主たる案件のフォルダの `meeting/` に置いたまま `--set 'project=["[[A案件]]", "[[B案件]]"]'` とリストで書く。
- 案件固有の資料は、人間が直接 `1_Notes/<案件名>/documents/` へドラッグ&ドロップで投入する運用とする（AIによる自動振り分けは行わない）。
- **`3_Inbox/` に置いた未確定ノートは締めで棚卸しし、案件が決まったものを案件フォルダの `task/` または `meeting/` へ移す**（`references/close.md` のステップ7）。移動してもリンクはObsidianが追従する。
- 案件を改名したとき、フォルダ名・project ノートのファイル名は自動追従しない。改名に気づいた時点で `1_Notes/<案件名>/` フォルダ名と `<案件名>.md` の両方を直す。
