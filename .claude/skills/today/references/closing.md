# today: 締め手順（旧wrapup）

あなたはこのObsidian vaultの「1日の終わり」の締め処理を担当する。**今日の分だけ**をその場で自動修正する日次の締めの儀式である。

## 対象の特定

「今日」とは以下のいずれかを満たすノートを指す。
- frontmatterの`date`が今日の日付
- ファイルの更新日時（mtime）が今日

## 前提確認

1. 今日の日付を確認する。
2. `20_Diary/<今日の日付>.md`が存在するか確認する。
   - 存在しない場合: `today`スキルの開始手順（`references/opening.md`）が未実行の可能性がある旨をユーザーに伝える。手順4・6（デイリーノートに依存する処理）はスキップし、他の手順は続行する。なお前提確認手順3（ブランチ確認）は、デイリーノートの有無にかかわらず実行する。
   - 存在する場合: 手順3へ進む。
3. `references/branch-check.md`の手順で、今日の日次ブランチを確認・切り替え・作成する。
   - 手順7のマージ対象ブランチを取り違えないよう、ここで確定させる。

## 手順

1. **`context`補完（自動）**: `30_Work/`・`40_Knowledge/`・`10_Inbox/`配下の`type`が`task`/`meeting`/`know-how`のノートのうち「今日」に該当し、`context`が空欄のものを探す。
   - 本文中にプロジェクトノート（`type: project`）への`[[...]]`リンクが**ちょうど1つだけ**存在する場合、それを`context`に設定する。
   - 本文にリンクが無い、または複数ある場合は自動設定せず、対象ノート名を「要確認リスト」に追加する（誤った紐付けを機械的に行わない）。
2. **議事録のアクションアイテムのタスク化（自動）**: 「今日」に該当する`type: meeting`ノートそれぞれについて、`references/meeting/action-items.md`の手順を対象ノートに適用する。
3. **AI議事録の転記（自動、利用可能なら）**: 「今日」に該当する`type: meeting`ノートのパス一覧を`references/meeting/ai-transcript.md`に渡し、その手順を適用する。
4. **今日のタスク確認・完了反映**: `20_Diary/<今日の日付>.md`の`## 今日のタスク`見出し配下を確認する。
   - チェック済み`- [x] [[ノート名]]`項目について、リンク先の`ノート名`が`type: task`のノートとして存在すれば、その`status`を`3_done`に更新する。
   - 未チェック`- [ ]`項目は一覧にする（従来通り）。
   - 一覧化の際、`references/task-note.md`の注記ルールに従い期限超過の注記を付ける。
5. **明日の準備**: 明日の日付（今日+1日）を計算し、`30_Work/`配下で`due`が明日の日付のタスクを一覧にする。
   - 利用可能なカレンダーMCPツール（Google Calendar・Outlook）があれば、明日の予定も取得して一覧に含める。
   - 使えるツールが無い場合はスキップし、エラーにしない。
6. **今日作成・更新したノートへのリンク一覧を最新化**: `references/note-list.md`の手順とその「書き込み方」に従い「今日作成・更新したノート」リストを生成・反映する。
   - 更新で既に同じ処理を実行しているが、1日の最終版としてここで再度最新化する。
7. **コミット・main統合・push**:
   - `git status`でこのブランチ上に変更があるか確認する。
   - 変更が無ければこの手順はスキップする。
   - 変更があれば`git add -A`してひとつのコミットにまとめる（コミットメッセージ例: `today: <今日の日付>`）。
   - `main`へ`git checkout`し、今日の日次ブランチ（`daily/<今日の日付>`）を`git merge --ff-only`でfast-forwardマージする（`--ff-only`指定により、fast-forwardできない場合はコマンドがエラー終了し、意図しないマージコミットの作成を防ぐ）。
   - Fast-forwardできない場合（`main`が日次ブランチの分岐後に進んでいる場合）：
     - `git checkout daily/<今日の日付>`で日次ブランチへ戻す。
     - mergeを中断し、その旨をユーザーに報告して判断を仰ぐ。
     - 強制マージ・リベースを自動実行せず、push・ブランチ削除も行わない。
   - Fast-forwardマージに成功した場合のみ、以下を実行する：
     - `git push origin main`を実行する。
     - マージ済みの日次ブランチを`git branch -d`で削除する。

## 報告

以下をまとめてユーザーに報告する。
- `context`を自動設定した件数・対象ノート名
- タスク化したアクションアイテムの件数・作成したタスクノート名
- `context`が要確認のノート一覧（自動設定できなかったもの）
- AI議事録を転記した件数・対象ノート名（転記が無ければ「該当なし」）
- 今日のタスクで未完了の項目一覧
- 今日のタスクから完了処理したタスク件数・対象ノート名
- 明日`due`のタスク・明日の予定の一覧
- デイリーノートに追記した「今日作成・更新したノート」件数
- コミット・マージ・pushの結果（変更が無くスキップした場合はその旨）
