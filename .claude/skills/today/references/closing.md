# today: 締め手順（旧wrapup）

あなたはこのObsidian vaultの「1日の終わり」の締め処理を担当する。`/audit`
（いつでも実行できるvault全体の読み取り専用の診断・報告）や`task`スキル
（`.claude/skills/task/SKILL.md`、vault全体を対話的に棚卸するツール）とは
役割が異なり、こちらは**今日の分だけ**をその場で自動修正する日次の締めの
儀式である。

## 対象の特定

「今日」とは以下のいずれかを満たすノートを指す。
- frontmatterの`date`が今日の日付
- ファイルの更新日時（mtime）が今日

## 手順

1. 今日の日付を確認する。また、Gitブランチを確認する。今日の日付の
   `daily/<今日の日付>`ブランチにいなければチェックアウトする（無ければ
   `main`から`git checkout -b daily/<今日の日付>`で新規作成する）。手順13の
   マージ対象ブランチを取り違えないよう、ここで確定させる。
2. **`context`補完（自動）**: `30_Work/`・`40_Knowledge/`・`10_Inbox/`配下
   の`type`が`task`/`meeting`/`know-how`のノートのうち「今日」に該当し、
   `context`が空欄のものを探す。本文中にプロジェクトノート（`type: project`）への`[[...]]`
   リンクが**ちょうど1つだけ**存在する場合、それを`context`に設定する。
   本文にリンクが無い・複数ある場合は自動設定せず、対象ノート名を
   「要確認リスト」に追加する（誤った紐付けを機械的に行わない）。
3. **議事録のアクションアイテムのタスク化（自動）**: 「今日」に該当する
   `type: meeting`ノートそれぞれについて、`.claude/skills/meeting/SKILL.md`
   （実体は`references/action-items.md`）の手順を対象ノートに適用する。
4. **AI議事録の転記（自動、利用可能なら）**: 利用可能な
   Microsoft 365/Teams のMCPツールがあれば、「今日」に該当する
   `type: meeting`ノートそれぞれについて、ノートのタイトル・日付・出席者
   と一致する会議を検索し、AI議事録ツール（Copilot等）が生成した議事録
   （要約・文字起こし等）を取得する。一致する会議が見つかれば、そのノートに
   `## AI議事録`見出しが既に存在する場合はその配下を取得内容で置き換える。
   存在しない場合（今回のテンプレート拡充より前に作成されたノート）は、
   旧`## Copilot議事録`見出しがあればそれを`## AI議事録`に改名した上で
   配下を置き換え、どちらの見出しも無ければノート末尾に`## AI議事録`見出し
   を新設して記載する（同じノートに`## AI議事録`と`## Copilot議事録`が
   並存する状態を作らない）。`## アクションアイテム`等の他の見出しは変更
   しない。取得内容からアクションアイテムを自動タスク化はしない（精度が
   不明なため、参考情報として並置するに留める）。ツールが利用できない・
   一致する会議が見つからない場合はこの手順をスキップする（エラーにしない、
   既存の`## AI議事録`欄はそのまま）。
5. **今日のタスク確認・完了反映**: `20_Diary/<今日の日付>.md`が存在すれば、
   `## 今日のタスク`見出し配下を確認する。
   - チェック済み`- [x] [[ノート名]]`項目について、リンク先の`ノート名`が
     `type: task`のノートとして存在すれば、その`status`を`3_done`に更新
     する。
   - 未チェック`- [ ]`項目は一覧にする（従来通り）。一覧化の際、下記
     「タスク注記」のルールに従い期限超過の注記を付ける。
6. **メモ欄の棚卸（提案のみ、実行はユーザー承認後）**: 同ノートの`## メモ`
   見出し配下の項目を確認し、固有名詞・後で参照しそうな具体的情報を含む
   など「単独ノートとして残す価値がありそうなもの」があれば、昇格候補と
   して提示する。空欄・雑多な走り書きだけの項目は候補にしない。
   ユーザーが承認したものだけ、`memo`スキル（`.claude/skills/memo/SKILL.md`）の
   手順で`10_Inbox`へ新規ノートとして切り出す。ユーザーの承認無く自動では
   切り出さない。
7. **明日の準備**: 明日の日付（今日+1日）を計算し、`30_Work/`配下で
   `due`が明日の日付のタスクを一覧にする。利用可能なカレンダーMCPツール
   （Google Calendar・Outlook）があれば、明日の予定も取得して一覧に含める
   （使えるツールが無い場合はスキップし、エラーにしない）。
8. **`10_Inbox`メモの昇格判定（提案のみ、実行はユーザー承認後）**:
   `10_Inbox/`直下にある`type`プロパティを持たないノート（memo）を対象に、
   内容を読んで「`task`/`meeting`/`know-how`のいずれかへ昇格させる価値が
   ありそうか」を判定する。判定基準は手順6と同様（固有名詞・後で参照し
   そうな具体的情報を含む等、「単独ノートとして残す価値がありそうなもの」）。
   空欄・雑多な走り書きだけのメモは候補にしない。
   - 昇格候補があれば、適切な`type`（`task`/`meeting`/`know-how`のいずれか）
     の判定案を添えて一覧をユーザーに提示し、承認を求める（自動実行しない。
     誤判定によって不適切な型を機械的に押し付けるリスクが高いため）。
   - 承認されたノートのみ、該当する`type`のfrontmatterを付与する。
     `date`は今日の日付とする。`context`は本文中の`[[...]]`リンクが
     ちょうど1つだけ存在する場合はそれを設定し、複数・無い場合は空欄にした
     上で手順2と同じ「要確認リスト」に追加する。`type: task`の場合は
     `status: 1_todo`をデフォルト設定する。
   - 昇格したノートは、直後の手順9・10の自動整理ロジックに乗せて`30_Work`/
     `40_Knowledge`へ移動する（型に応じた通常の移動先判定ルールに従う）。
   - 承認されなかった・判断できなかったノートは`10_Inbox`にそのまま残す
     （従来通り）。
   - 昇格候補が無ければこの手順はスキップする。
9. **`30_Work`のプロジェクトフォルダへの自動整理**: `30_Work/`直下（サブ
   フォルダの外）にある`type: project`ノートごとに、`30_Work/<ノート名>/`
   フォルダが無ければ作成する。そのノート自身と、`context`がそのノートを
   指す`type: task`/`meeting`のノートのうち`30_Work/`直下または`10_Inbox/`
   直下にあるものを、まとめてそのフォルダへ移動する（`10_Inbox/`直下の
   対象は`type`プロパティを持つノートに限り、`type`を持たないmemoノートは
   対象外のまま`10_Inbox`に残る。昇格判定は手順8を参照）。`context`が
   空欄のノートは対象外（直下に残す）。「今日」に限定せず、`30_Work/`・
   `10_Inbox/`直下にあるものは毎回全件対象にする（放置させないため）。
   内部リンクの自動更新設定が有効なため、移動してもリンク切れは起きない。
10. **`40_Knowledge`のカテゴリフォルダへの自動整理**: `40_Knowledge/`直下・
    `10_Inbox/`直下（いずれもサブフォルダの外）にある`type: know-how`
    ノートを対象に、内容を読んで適切なカテゴリを判断する（`10_Inbox/`
    直下の対象は`type`プロパティを持つノートに限り、`type`を持たない
    memoノートは対象外のまま`10_Inbox`に残る。昇格判定は手順8を参照）。
    `40_Knowledge/`内に既存のサブフォルダがあれば最も内容が合致するものを
    優先的に使い、無ければ新しいカテゴリ名でサブフォルダを作成して移動
    する。ノウハウは複数プロジェクトで再利用される前提のため、`context`
    （プロジェクト）ではなくカテゴリ（内容の種類）で分類する。こちらも
    「今日」に限定せず、`40_Knowledge/`・`10_Inbox/`直下にあるものは毎回
    全件対象にする。
11. **プロジェクトノートの進捗サマリー更新（自動）**: 「今日」に該当する
    `type: task`/`meeting`/`know-how`ノートのうち`context`が設定されている
    ものを集め、リンク先のプロジェクトノート（`type: project`）を重複排除して列挙
    する。該当するプロジェクトノートごとに、そのプロジェクトへ`context`でリンクする全ノート
    （日付を問わず全期間）を読み、タスクの完了状況（件数・直近ステータス）・
    直近の議事録の要点・ノウハウの有無を踏まえて3〜5行程度の日本語サマリー
    を作成し、プロジェクトノートの`## 進捗`見出し配下のサマリー本文
    （プレースホルダーの説明文、または過去に生成した本文）だけを置き換える。
    `> [!TIP]-`のBase埋め込みブロックは`## 進捗`見出し配下にあっても既存
    セクションとして扱い、変更・削除しない。`## 進捗`見出しが無い場合は
    frontmatter直後に新設する。対象プロジェクトが無ければこの手順はスキップ
    する。
12. **今日作成・更新したノートへのリンク一覧を最新化**:
    `20_Diary/<今日の日付>.md`が存在しない場合（`today`スキルの開始手順
    未実行のままこの締め手順を呼んだ場合等）はこの手順をスキップする
    （エラーにしない）。存在する場合、vaultルートで
    `git status --short -- 30_Work 40_Knowledge 10_Inbox`を実行し、
    `opening.md`手順9と同じルール（`??`＝作成、`M`等＝更新、同名の
    `D`+`??`ペアはフォルダ移動として「更新」扱い）でtypeごとに
    グルーピングした`- [[ノート名]]（作成）`/`- [[ノート名]]（更新）`
    のリストを作る。`20_Diary/<今日の日付>.md`の`## 今日作成・更新した
    ノート`見出し配下を、このリストで置き換える（開始手順・途中確認が
    同じ処理を実行時に行っているが、1日の最終版としてここで再度最新化
    する）。見出しが無ければ`## メモ`見出しの直前に新設する。`## メモ`
    欄は手動更新されるため、常にノートの最後尾に保つ。
13. **コミット・main統合・push**: `git status`でこのブランチ上に変更が
    あるか確認する。変更が無ければこの手順はスキップする。変更があれば
    `git add -A`してひとつのコミットにまとめる（コミットメッセージ例:
    `today: <今日の日付>`）。`main`へ`git checkout`し、今日の日次ブランチ
    （`daily/<今日の日付>`）を`git merge`でfast-forwardマージする。
    fast-forwardできない場合（`main`が日次ブランチの分岐後に進んでいる場合）
    は`git checkout daily/<今日の日付>`で日次ブランチへ戻した上でmergeを
    中断し、その旨をユーザーに報告して判断を仰ぐ（強制マージ・リベースを
    自動実行せず、push・ブランチ削除も行わない）。fast-forwardマージに
    成功した場合のみ、`git push origin main`を実行し、マージ済みの日次
    ブランチを`git branch -d`で削除する。

## タスク注記

手順5で未完了タスクを一覧化する際、`due`/`check`の期限超過を
`- [ ] [[ノート名]]**（due YYYY-MM-DD超過）**`の形式で注記する。以下の優先
順位で1つだけ注記する。

1. `due`が設定されており今日以前 → `**（due YYYY-MM-DD超過）**`。ただし
   `due`が今日と同日なら「超過」を付けず `（due YYYY-MM-DD）`とする。
2. 上記に該当せず`check`が設定されており今日以前 → `**（check YYYY-MM-DD超過）**`。
   同様に`check`が今日と同日なら「超過」を付けない。

## 報告

以下をまとめてユーザーに報告する。
- `context`を自動設定した件数・対象ノート名
- タスク化したアクションアイテムの件数・作成したタスクノート名
- `context`が要確認のノート一覧（自動設定できなかったもの）
- AI議事録を転記した件数・対象ノート名（転記が無ければ「該当なし」）
- 今日のタスクで未完了の項目一覧
- 今日のタスクから完了処理したタスク件数・対象ノート名
- メモ欄からの昇格候補（あれば、ユーザーに可否を確認する）
- `10_Inbox`メモの昇格候補（あれば、type案とともにユーザーに可否を確認する）・
  承認結果（昇格・移動した件数と対象ノート名、または「該当なし」）
- 明日`due`のタスク・明日の予定の一覧
- 進捗サマリーを更新したプロジェクトノート件数・対象ノート名
- `30_Work`・`40_Knowledge`で整理（移動）したノート件数と移動先
- デイリーノートに追記した「今日作成・更新したノート」件数
- コミット・マージ・pushの結果（変更が無くスキップした場合はその旨）
