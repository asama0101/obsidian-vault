# today: 更新手順

あなたはこのObsidian vaultのデイリーノートを、カレンダー・今日のタスク・今日作成/更新したノートの最新状態に同期する「更新」処理を担当する。
開始処理（`references/opening.md`）実行後、日中いつでも単独で呼び出される。
1日に何度呼び出しても安全である（既存議事録ノートは再質問せず、削除は必ず確認を挟む）。

## スコープ判定

ユーザー発言から更新範囲（スコープ）を判定する。

1. 発言に含まれるキーワードで判定する。
   - 「予定」「スケジュール」「カレンダー」を含む → **カレンダーのみ**（「〜だけ」「〜のみ」等の修飾語の有無を問わない。例: 「スケジュール更新して」「予定変わったから反映して」「予定を再取得して」はすべてこれに該当する）
   - 「タスク」を含む → **タスクのみ**
   - 「ノート」を含む → **ノートのみ**
   - 「全部」「すべて」「まとめて」等を含む → **全部**
   - 上記のいずれにも該当しない、または複数カテゴリのキーワードに同時に該当する場合 → `AskUserQuestion`で「更新範囲はどれですか？」を確認する。選択肢: `カレンダーのみ` / `タスクのみ` / `ノートのみ` / `全部`。
2. 判定結果を`スコープ`として、以降の各ブロックの実行可否に使う。

## 前提確認

1. 今日の日付（`YYYY-MM-DD`形式）を確認する。
2. `20_Diary/<今日の日付>.md`が存在するか確認する。
   - 存在しない場合: 開始処理（`references/opening.md`）が未実行なので、その旨をユーザーに伝えて中断する（このファイル自体は作成しない）。
   - 存在する場合: 手順3へ進む。
3. `references/branch-check.md`の手順で、今日の日次ブランチを確認・切り替え・作成する。
   - 注記: 前提確認手順2で当日ノートが既に存在することを確認済み＝`references/opening.md`が実行済みの可能性が高いため、他日の`daily/*`ブランチ残存に対するstale-branch警告（`opening.md`側の追加チェック）はここでは行わない。

## カレンダー再同期（スコープ: カレンダーのみ/全部）

1. 利用可能なカレンダーMCPツール（Google Calendar・Outlook）を確認する。
   - 使えるツールが無い場合:
     - ユーザーにその旨を伝える。
     - このブロックをスキップする（エラーにしない）。
     - スコープが`全部`の場合は、続けて「タスク再計算」「ノート一覧再生成」ブロックを実行する。
2. 当日の最新の予定を取得する。予定のうち「会議候補」（`references/meeting/calendar-candidate.md`の基準）を特定する。
3. **会議候補の処理**:
   - 手順2で「会議候補」が1件以上ある場合: `references/meeting/calendar-candidate.md`の手順に従い、デイリーノートの現在の`## スケジュール`欄テキストとともに各会議候補に適用する（開始時刻順）。各候補について`ノートあり`・`不参加`のいずれかの結果を得る。
   - 会議候補が0件の場合: この手順はスキップする。
4. **`## スケジュール`欄の全件洗い替え**:
   - 取得した今日の予定のうち手順3の結果が`不参加`だったものを除いて、開始時刻順に`## スケジュール`見出し配下へ書き込む（既存の内容は置き換える。書式は`references/meeting/calendar-candidate.md`の「スケジュール欄の書式」を参照）。
   - 会議候補への反映（`### 不参加`欄への振り分け・議事録ノートへのリンク埋め込み）は`references/meeting/calendar-candidate.md`の「呼び出し元での結果の使い方」に従う。
5. **議事録の削除候補の検出**:
   - `30_Work/`配下の`type: meeting`ノートのうち「今日」（frontmatterの`date`が今日、またはファイルの更新日時（mtime）が今日。`references/closing.md`の「対象の特定」と同じ基準）に該当するものを走査し、それぞれのfrontmatterから`calendar_event_id`を読み取る。
   - 手順2で取得した今回の会議候補一覧の中に、同じ`calendar_event_id`を持つ予定が存在しなければ、そのノートを「削除候補」とする。
   - 検出する対象: 予定が無くなった場合・会議候補の条件を満たさなくなった場合の両方。
   - `calendar_event_id`が空欄のノート（手動作成分）は削除候補の対象外とする。
6. **削除候補の確認・実行**: 削除候補が1件以上あれば、各ノートについて本文がテンプレートのまま（`## 議題`等の見出し配下が空欄）か、何らかの追記があるかを一言添えた一覧をユーザーに提示し、削除してよいか確認する。
   - 承認されたノートのみ、Obsidian vaultから削除し、`## スケジュール`欄の対応する行のリンクを除去する（タイトルをプレーンテキストに戻す）。
   - 承認されなかった・確認できなかったノートは、ノート本体・`## スケジュール`欄のリンクの両方をそのまま残す。
   - 削除候補が無ければこの手順はスキップする。

## タスク再計算（スコープ: タスクのみ/全部）

1. **`## 今日のタスク`欄の再計算**: 既存の`## 今日のタスク`見出し配下を、以下の手順で書き換える（テキストの部分保持ではなく毎回全体を作り直す）。
   1. 既存の各行から`- [x] [[ノート名]]`形式のチェック済みノート名を「チェック済みノート名リスト」として記録する。
   2. `references/task-note.md`の検索条件で対象タスクを再検索する。
   3. 同ファイルの出力構造（期限超過グループ／`context`ごとのグループ化）に従って全体を組み立てる。各行のチェック状態は、1.の「チェック済みノート名リスト」に含まれていれば`- [x]`、含まれていなければ`- [ ]`とする。
   4. 組み立てた内容で`## 今日のタスク`見出し配下を丸ごと置き換える。
   - 注意: チェック済みだったノートでも、`status`変更や`due`/`check`編集により2.の再検索条件から外れた場合は一覧から消える（部分保持はしない）。

## ノート一覧再生成（スコープ: ノートのみ/全部）

1. `references/note-list.md`の手順とその「書き込み方」に従い「今日作成・更新したノート」リストを生成・反映する。

## 常時実行

`## 繰り返しのタスク`・`## メモ`欄は対象外（手動管理のまま変更しない）。

## 報告

実際に実行したスコープの内容のみをユーザーに報告する（実行しなかったカテゴリの項目は報告に含めない）。

- スコープが`カレンダーのみ`または`全部`の場合:
  - スケジュール欄の変更点（追加・削除・時刻変更された予定、`### 不参加`欄への追加を含む）
  - 新規生成した議事録ノート件数・対象ノート名（無ければ「該当なし」）
  - `## スケジュール`欄に追加したリンク件数・対象会議名（無ければ「該当なし」）
  - 削除候補として提示したノート件数・対象ノート名、承認結果（削除した/残した）
- スコープが`タスクのみ`または`全部`の場合:
  - `## 今日のタスク`欄で新規追加・除外された項目（チェック状態は保持される旨）
- スコープが`ノートのみ`または`全部`の場合:
  - `## 今日作成・更新したノート`欄の更新有無
