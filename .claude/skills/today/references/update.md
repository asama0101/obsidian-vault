# 更新モード

日中に秘書ループを回し続ける。`/loop` から30分間隔で自動的に呼ばれる。日次ブランチ（`daily/<今日の日付>`）にいて、当日のデイリーノートが既にある場合に起動する。

## 日次ノート再生成

1. 必要な索引を `index.py` で取得する。**個別ノートを1件ずつ読んではならない。**これが本来の制約であり、呼び出し回数そのものではない。1サイクルの `index.py` 呼び出しは数回に収め、ノート件数に比例させない。
2. カレンダーを1回だけ引く。以降のステップは取得済みのイベント一覧を使い回す。
3. `Cabinet/MEMORY.md` を読む。分類と `tags` の推定に使う。
4. **`## 今日のタスク` のチェック済み行（`- [x]`）を完了の合図として扱う。** 対応するタスクノートの `status` を `4_done`、`done` を今日の日付にする。状態はノート側の frontmatter が持つため、次のステップの全置換で当該タスクは一覧から外れる。冪等性は保たれる。
5. **`## 今日の予定` のチェック済み行（`- [x]`）を出席の合図として扱う。** 対応する議事録ノートの `status` を `2_実施済` にする。状態はノート側の frontmatter が持つため、次のステップの全置換でチェックは復元され、冪等性が保たれる。
6. **カレンダーに新しく現れたイベントの議事録ノートを作る。** 開始モードのステップ6と同じ照合・生成を行う（`index.py --type meeting --date <今日> --with-calendar-ids` の `calendar_event_id` 列と照合し、無ければ `new_note.py` で作る）。定例なら前回の同シリーズ議事録から `## アクション` の未完分と `## 議題` を転記する。**ここでは Explore への並列委任は行わない。** 日中に会議が追加されたとき `## 今日の予定` にリンクだけが並んで実体が無い状態を作らないため。
7. **会議のキャンセル判定を行う。**
   - 対象: `index.py --type meeting --date <今日> --with-calendar-ids` が返す行のうち `status` が `1_予定` のものだけに限る。
   - 実行: そのうち `calendar_event_id` が今日のカレンダーに存在しないものを `3_中止` にする。

   **`date` が今日でない過去の議事録には絶対に触れない。** このモードは前回状態を保存しないため、対象を今日かつ `1_予定` に絞らないと「今日のカレンダーに無い」＝「過去の全議事録」となり、30分ごとに過去の記録を書き換えてしまう。
8. `## 今日の予定` と `## 今日のタスク` を**全置換で再生成**する。開始モードと同じ抽出条件を使う。ステップ4〜7でノートの状態を先に確定させてから書くため、リンク切れも完了済みタスクの再掲も起きない。

## `## メモ`・`## 確認したいこと` 処理

9. `## メモ` の未処理行（`references/diary-note.md` の「処理済みマーカーの判定規約」に従い、AIの接頭辞（`⚠`/`ⓘ`/`前日の未処理:`）を持たず、かつ `→ [[...]]` や `→ 実行済み` を含まない行）を1行ずつ次のいずれかとして処理する。既定は**捕捉**であり、**既存ノートへの操作指示**として扱うのは次の条件を両方満たす場合に限る（既定を捕捉に振っているため、この条件は狭く取る）。

   **既存ノートへの操作指示と判定する条件（両方満たす場合のみ）:**
   - (1) 変更内容が `tags` の付け替え・`status` の変更・`due` の変更のいずれかである
   - (2) メモ行が既存ノートを `[[リンク]]` で名指ししているか、既存ノートの `title` と一致する語を含んでいて対象ノートが一意に特定できる

   「A社の件は来週まで延期」のように読み方が割れる行は、リンクも `title` 一致も無ければ操作指示と誤解釈しない。誤って操作指示扱いすると、ノートが作られないまま ` → 実行済み` が付いて処理済み扱いになり、`status`/`due` の誤実行が締めの未処理棚卸しにも表れず検知経路を失うため。

   **操作指示と判定した場合の実行手順:**
   - ノート化せず指示として直接実行する
   - 実行後、行の後ろに ` → 実行済み（<何をしたか>）` を追記する
   - `tags` の変更は対象ノートの frontmatter を直接編集する
   - 同じ値を持つ他のノートも直す必要がある場合は `index.py` の `tags` 列で対象ノートを列挙し、frontmatterを1件ずつ直接編集する
   - ノートの削除や本文の書き換えは対象外とし、その種の指示は会話で受ける

   **条件を満たさない場合（既定・捕捉）:** `new_note.py` でノート化し、行の後ろに ` → [[ノート名]]` を追記する。
10. `## 確認したいこと` の回答済み行（`→` の右に文字がある行）を処理し、ノート化した上でその行をチェック済み（`- [x]`）にして残す（削除しない）。元になった `## メモ` 行があれば、その行の後ろにも ` → [[ノート名]]` を追記して未処理状態を解消する。

## 終了会議の事後構造化

11. **終了時刻を過ぎた会議の事後構造化を行う。** `## メモ` の生メモから `## 決定事項` と `## アクション` を抽出して議事録ノートに書き、アクションはタスクノートとして起票して議事録からリンクする。**`status` はこのステップで変更しない。**出席の確定はチェックボックスが担い、未チェックのまま終了時刻を過ぎた行は締めモードの出欠確認に回る（`references/close.md` 参照）。

## タグ棚卸し

12. **今日作ったタグの棚卸しを行う。このステップは更新モードの最後に置く。**
    - 対象の判定: `index.py --updated-on <今日>` の出力だけを使う。`tags` 列に現れる値のうち、`Cabinet/Bases/` のどの `.base` にも view が無いものを「今日新しく生まれたタグ」とする。**フィルタ無しの全件呼び出しは行わない。**
    - 出力: 該当があれば `## メモ` の先頭に `- ⓘ 今日作ったタグ: <値1>, <値2>（違っていればObsidianのタグ機能で改名。締めで .base に view を足します）` の1行を追記する。該当が無ければ何もしない。
    - **値は昇順に並べる。** 並び順が揺れると毎サイクル「構成が変わった」と誤判定される。
    - **同じ内容の行が既に `## メモ` にあれば追加しない。値の構成が変わっていれば既存のⓘ行を書き換える。**
    - **更新モードの最後に置くのは**、ステップ10・11より前だと、それらが新しいタグを作った場合にそのサイクルで告知されないため。
    - **締めモードではなく更新モードに置くのは、締めモードで書くと人間の目に触れないためである。** 締めは人間がその日のデイリーノートを見終わったあとに走る。

このモードは冪等である。前回の状態を保存する必要はない。

`## メモ` と `## 確認したいこと` に対しては追記と処理済み行の削除だけを行い、人間が書いた文言を書き換えない。ただしAI自身が書いた `⚠` 行・`ⓘ` 行の書き換え（内容変化時の上書き）はこの制約の対象外とする。人間の文言ではないため。
