# today

Obsidian vaultで秘書業務を回す。人間との接点はデイリーノート1枚だけ、`Cabinet/Notes/` の一覧取得は `index.py` だけ、分類基準は `references/classification.md` だけ。

デイリーノートは `Cabinet/Diary/<今日の日付>.md` である。作成時からこの場所に置き、以後移動しない。

## モードの判別

締め・取り込み・プロジェクト管理アクションは他の条件と直交するため、先に判定する。

- 「締めて」「クリアデスク」等の明示指示 → **締めモード**
- 会話にメール・チャット等の本文が貼られている → **取り込み**
- 「〇〇にタスク追加して」「棚卸しして」等の明示指示 → **プロジェクト管理アクション**（`references/project-management.md` 参照）。既存4モードのブランチ／ファイル状態判定とは独立した会話内アクション。
- どちらでもない場合は、`git branch --show-current` でブランチを確認してから、当日ファイルの有無と組み合わせて下の表で判定する。

| 現在のブランチ | `Cabinet/Diary/<今日>.md` | 判定 |
|---|---|---|
| `main` | 無し | 開始モード |
| `main` | 有り | 開始モード（ブランチだけ作り直す。締めが成功した後に同じ日でもう一度「今日のノートを開いて」等と伝えた場合、または締めが push で失敗して `main` 上に残った場合） |
| `daily/<今日>` | 有り | 更新モード |
| `daily/<今日>` | 無し | 開始モード（前回の開始がブランチ作成後に中断した場合。既存ブランチを使い回す） |
| `daily/<今日以外>` | — | **停止**。前日分が未締め |
| 上記以外 | — | **停止**。想定外のブランチ |

判別をブランチで行うのは、デイリーノートを最初から `Cabinet/Diary/` に作るため。過去分も常に同じ場所にあるので、ファイルの存在では前日未締めを検知できない。締めは必ず `main` 上で終わるため、日次ブランチに居残っていること自体が未締めの証拠になる。

表の2行目（`main` かつ当日ファイル有り）は、締めが成功した直後に同じ日でもう一度「今日のノートを開いて」等と伝えたときにも起きる。締めは HEAD を `main` に残すので、この経路が最も頻度が高い。このとき開始モードが走るが、既存の当日ファイルは作り直さずそのまま使い（開始モードの第2項）、`## 今日の予定` と `## 今日のタスク` だけが全置換で再生成される。`## メモ` と `## Claudeからの連絡` は全置換の対象外なので、人間が書いた内容はそのまま残る。

**停止**と判定した場合は人間に報告し、自動では先へ進まない。報告する内容は次のとおり。

- `daily/<今日以外>` の場合: 「`<ブランチ名の日付>` 分が締められていない」と伝え、`Cabinet/Diary/<ブランチ名の日付>.md` の有無で復旧手順を書き分ける。
  - ファイルが有る場合: 「『締めて』と伝えて締めてから、あらためて『今日のノートを開いて』等と伝えること」と伝える。
  - ファイルが無い場合: 「`git checkout main` で `main` へ戻ってから『今日のノートを開いて』等と伝えること」と伝える。この行の判定は当日ファイルの有無を問わないため、開始モードがブランチ作成直後に中断して日をまたぐとこの状態に到達する。締めるべき記録が無いので締める必要はなく、「締めて」と伝えても `<ファイル名> がありません` で終了コード1になる。
  - あわせて、前日の締めが `main` への fast-forward マージ失敗で止まっていた場合は締め処理を再実行しても同じ地点で再び失敗するため、先に `main` 側を解決する必要があることも伝える。
- 想定外のブランチの場合: 現在のブランチ名を示し、`main` か当日の日次ブランチへ移ってから「今日のノートを開いて」等と伝えるよう促す。

締めは時刻では起動しない。人間が退勤したかを時刻から推定できないため。

## 詳細は以下を参照

モード別:

- `references/common.md` — 全モードに共通する前提（ブランチ・コミット・索引読み取り・通知禁止）
- `references/start.md` — 開始モードの手順
- `references/update.md` — 更新モードの手順
- `references/close.md` — 締めモードの手順（正典）。締めは1日1回しか使わないため、起動したら全文読む前提で書かれている
- `references/intake.md` — 取り込みモードの手順

会話内アクション別:

- `references/project-management.md` — タスク追加・棚卸しの手順（4モードとは独立した会話内アクション）

対象ノート/セクション別:

- `references/diary-note.md` — デイリーノートの行書式と処理済みマーカーの判定規約
- `references/classification.md` — ノートの分類基準と確信が持てないときの扱い
- `references/tags.md` — タグの第1階層・付与対象のルール
- `references/note-placement.md` — ノートの初期配置（案件フォルダ／直下）ルール
- `references/calendar.md` — カレンダー取得・絞り込みルール
- `references/note-editing.md` — 既存ノートのプロパティ編集ルール
- `references/scripts.md` — index.py / new_note.py / close_day.sh のチートシート
