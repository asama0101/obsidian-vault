# 更新モード

1. `Inbox/`配下の各ノートを走査する。ノートが無ければ2以降をスキップして
   Reviewスキャンへ進む。
2. 各Inboxノートについて、`context`（既存プロジェクト名等）と種別
   （task/project/meeting/know-how）の両方が本文から明確に読み取れるか
   判定する。
   - 両方明確 → 判定したtypeのテンプレート（`Cabinet/Templates/{type}.md`）
     を元に`Cabinet/Notes/`へノートを作成し、Inboxの元ノートを削除する。
     新規プロジェクト作成が必要と判断される内容の場合は自動作成せず、
     次の分岐（不明瞭）として扱う。
   - どちらか不明瞭、または新規プロジェクト起票が必要 → Inboxノートは
     そのまま残し、`PushNotification`で「判断が必要」と即時通知する
     （何が不明瞭かを添える）。
3. `Review/`配下の各ノートを走査する。ノートが無ければ4以降をスキップする。
   各Reviewノートについて、`## 要判断`セクションの内容が作成時点から
   追記・変更されているか（＝人間が回答済みか）を確認する。
   - 回答済み → その回答内容と`## 本文`の内容から種別（type）と`context`
     を決定し、`Cabinet/Templates/{type}.md`を元に`Cabinet/Notes/`へ正式な
     ノートを作成する。作成後、元のReviewノートを削除する。
   - 未回答 → そのまま残す（何もしない）。
4. Google Calendarで予定の変更（新規追加・時刻変更・キャンセル）が無いか
   確認する。変更があれば該当する議事録ノート（`Cabinet/Notes/`）を生成・
   更新し、`Today.md`「ブリーフィング」の`### 今日の予定`を最新化する。
   取得失敗時は人間に通知する。
5. `Cabinet/Notes/`で`type: task`のノートのうち、`due`が今日以前
   （超過含む）で`status`が`4_done`/`5_cancelled`でないものを抽出する。
   前回の更新から新たに該当したものがあれば`PushNotification`で即時通知
   する。`Today.md`「ブリーフィング」の`### 今日のタスク`を最新化する。
6. `Today.md`の`## メモ`セクションには触れない。
