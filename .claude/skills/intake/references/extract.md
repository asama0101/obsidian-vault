# intake: 抽出・確認・起票

貼り付けられた本文（またはscan.mdから渡されたメッセージ）からタスク候補を抽出し、ユーザー確認を経てタスクノートを起票する。

## 入力

- メール・チャットの本文（貼り付け、またはscan.mdからの受け渡し）
- scan.md経由の場合は加えて: メッセージID・件名・差出人・context候補（件名ルール照合済み）

## 手順

1. **日次ブランチ確認**: `.claude/skills/today/references/branch-check.md`の手順を適用する。
2. **タスク候補の抽出**: 本文から依頼・宿題として意味を成す項目を抽出する（1メッセージから複数可）。各候補について以下を組み立てる。
   - タイトル案: 依頼内容の要約（ノートのファイル名になるため、ファイルシステムで使用できない文字は除去または`_`に置換する）
   - due候補: 本文に具体的な期日の明示がある場合のみ。相対表現（「次回定例まで」等）は自動で日付に解決せず空欄とし、手順3の選択肢説明にその表現を明記してユーザーの判断に委ねる
   - context候補: scan.mdから非空欄の候補が渡されていればそれを使う。渡された候補が空欄（件名ルール不一致）の場合・貼り付けモードの場合は、本文の内容と既存プロジェクトノート（`type: project`かつ`status: 1_active`）の名前・概要を照合して推定する。確信が持てなければ空欄
3. **ユーザー確認**: `AskUserQuestion`（multiSelect）で候補一覧を提示し、起票対象を選択させる。
   - 各選択肢にタイトル案・due候補・context候補を記載する。context候補が空欄の場合はその旨を明記する。
   - contextの指定・修正はOtherの自由入力で受け付ける。
   - 0件選択なら何も作らず終了する。
4. **起票**: 選択された各候補を`92_Template/task.md`をもとに`30_Work/`直下へ作成する。
   - frontmatter: `status: 1_todo`・`date`は今日・`due`は候補があれば設定・`context`は確定値（空欄可）
   - scan.md経由でメッセージIDが渡されている場合のみ、frontmatterに`source_id: <メッセージID>`を追加する（貼り付けモードでは追加しない）。1つのメッセージから複数タスクを起票した場合、同じ`source_id`が複数ノートに入ってよい（重複チェックはメッセージ単位で行われるため問題ない）
   - `## 完了条件`のチェックボックスに依頼内容を書く
   - `## メモ`に出典行を書く（例: `- 2026-08-31: 山田さんからのメール「○○の件」より起票`。チャットならリンクまたはチャネル名）
   - 同名ファイルが既に存在する場合は上書きせず、末尾に`_2`・`_3`...と連番を付与して回避する
5. **報告**: 作成したタスクノートのパス一覧を報告する。

## 出力

作成したタスクノートのパス一覧（0件の場合はその旨）。
