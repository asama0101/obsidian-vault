# meeting: 議事録ノートの新規作成

あなたはこのObsidian vaultの議事録ノート作成を担当する。テンプレートは
`92_Template/meeting.md`の1本のみで、「定例か否か」は判定しない。代わりに
同じプロジェクトの直近の議事録を探し、あれば未完了のアクションアイテムと
次回の議題を引き継ぐ。

`today`スキル（`.claude/skills/today/references/meeting.md`）等から呼び出される
場合、プロジェクト名の確認は呼び出し元が既に済ませているため、`context`・
`calendar_event_id`・`calendar_series_id`が呼び出し元から渡される。ユーザーから
直接呼ばれた場合（これらが渡されていない場合）は本ファイル内で確認する。

## 手順

1. **プロジェクト名の特定**: 呼び出し元から`context`（プロジェクトのwikilink、
   または「該当なし」の指定）が明示的に渡されている場合は、この手順をスキップ
   しそれをそのまま使う。渡されていない場合（ユーザーから直接呼ばれた場合）は、
   ユーザーの要望から対象のプロジェクト名を特定し、それに該当する「プロジェクト」
   ノート（`type: project`）を、`file.name`の完全一致・部分一致で`30_Work/`配下
   から検索する。0件・複数件該当する場合はユーザーに確認する（誤った紐付けを
   機械的に行わない）。
   - 見つかった場合: そのノートへのwikilink（例: `[[A社ネットワーク更改]]`）
     を`context`に使う。
2. 手順1で`context`が定まった場合、同じ`context`を持つ既存の議事録ノート
   （`type: meeting`）を`30_Work/`配下から検索し、`date`が最も新しいものを1件
   特定する。`context`が空欄（「該当なし」）で、かつ呼び出し元から
   `calendar_series_id`が渡されている場合は、代わりに同じ`calendar_series_id`
   を持つ既存の議事録ノートを`30_Work/`配下から検索し、`date`が最も新しいもの
   を1件特定する（`calendar_series_id`も渡されていなければこの手順は空振りで
   よい）。見つかった場合、そのノートの`## アクションアイテム`見出し配下の
   未チェック項目（`- [ ] [[ノート名]]`）のうち、ノート名が空（`[[]]`）でない
   ものを収集する（手順5で使う）。
   - **次回の議題の収集**: 呼び出し元から`calendar_series_id`が渡されている
     場合（定例会議の場合）は、上記とは別に、同じ`calendar_series_id`を持つ
     既存の議事録ノートを`30_Work/`配下から検索し、`date`が最も新しいものを
     1件特定する（同じプロジェクトに複数の定例シリーズが存在しうるため、
     「次回の議題」は`context`一致検索ではなく必ずこのシリーズ一致検索から
     取得する）。見つかった場合、そのノートの`## 次回`見出し配下の「議題」行
     （`- 議題: ...`）の内容を収集する（手順7で使う）。`calendar_series_id`が
     渡されていない場合、この項目は空振りでよい。
3. **重複判定とファイル名**:
   - 呼び出し元から`calendar_event_id`が渡されている場合: 今日該当する
     `type: meeting`ノートのうち、frontmatterの`calendar_event_id`が一致する
     ものを`30_Work/`配下から検索する。見つかった場合は新規作成せずスキップし、
     既存ファイルパスをユーザーに報告して以降の手順は行わない。見つからない
     場合、ファイル名は`<今日の日付>_<プロジェクト名>_<予定タイトル>.md`とする
     （`context`が「該当なし」の場合は`<今日の日付>_<予定タイトル>.md`）。
     予定タイトルはファイルシステムで使用できない文字（`/ \ : * ? " < > |`等）
     を除去または`_`に置換する。生成したファイルパスが偶然既に存在する場合は
     末尾に`_2`・`_3`...と連番を付与して回避する。
   - `calendar_event_id`が渡されていない場合（ユーザーから直接呼ばれた場合）:
     ファイル名は`<今日の日付>_<プロジェクト名>.md`とする。既に同じファイル
     パスのノートが存在する場合は、新規作成せずスキップする（人間が書き足した
     既存の議事録内容を無警告で上書きしないため）。その旨と既存ファイルパスを
     ユーザーに報告し、以降の手順は行わない。
   - いずれの場合も、決定したファイル名で`30_Work/`直下に作成する。
4. `92_Template/meeting.md`を使い、frontmatterの`date`を今日の日付、`context`
   を手順1の結果で埋める。呼び出し元から`calendar_event_id`・
   `calendar_series_id`が渡されている場合はそれぞれのfrontmatterに書き込む
   （渡されていなければ空欄のままにする）。
5. **前回のアクションアイテムの記載**: 手順2で収集したアクションアイテムが
   あれば、`## 前回のアクションアイテム`見出し配下に列挙する。呼び出し元から
   `calendar_series_id`が渡されている（定例会議の）場合は、項目ごとに対応する
   `ノート名`のファイルが`type: task`のノートとしてvault全体（`30_Work/`配下
   に限らず`10_Inbox/`等も含む）に既に存在するか確認し、
   存在すれば`- [[ノート名]]（タスク化済み・status: <取得したstatus値>）`
   形式で記載する（タスク自体がstatusで進捗を管理するため、チェックボックス
   は付けない）。存在しなければ`- [ ] [[ノート名]]`形式で記載する。
   `calendar_series_id`が渡されていない場合（定例でない場合）は、既存タスクの
   有無を確認せず、収集した全項目をそのまま`- [ ] [[ノート名]]`形式で列挙する。
   収集した項目が無ければ空欄のままにする。
6. **会議情報の記載**: 呼び出し元（`today`スキルの開始手順等）からカレンダー
   イベントのタイトル・URL（ビデオ会議リンクがあればそれ、無ければカレンダー
   イベント自体のURL）・出席者（参加者一覧）・開始時刻・終了時刻が渡されて
   いる場合、`## 会議情報`見出し配下の該当する項目（タイトル・URL・開始時刻・
   終了時刻）にそれぞれ記載し、出席者は`## 出席者`見出し配下に箇条書きで記載
   する。渡されていない場合（ユーザーから直接呼ばれた場合等）は該当欄を空欄の
   ままにする。`## 資料`欄は自動入力しない（常に空欄のまま、手動運用）。
7. **議題欄の初期値**: `## 議題`見出し配下の初期値を、以下の優先順位で決定
   する。
   1. 呼び出し元から`calendar_series_id`が渡されている（定例会議の）場合、
      手順2で取得した前回議事録の`## 次回`欄「議題」行に記載があれば、それを
      そのまま転記する。
   2. 上記に該当しない場合（定例でない・前回議事録が無い・前回の議題欄が空、
      のいずれか）、呼び出し元からカレンダーイベントのdescriptionが渡されて
      いれば、その内容を候補とする。ただしdescriptionが議題として意味を成す
      本文を含まない（URL・リンクのみ、または「Microsoft Teams 会議」「会議
      に参加するにはここをクリック」等の参加用定型文・電話番号・会議ID等の
      招待ボイラープレートのみで構成される）と判断される場合は自動転記せず、
      `AskUserQuestion`で「この予定の説明欄に議題として使えそうな記載が見当
      たりません。## 議題欄の初期値はどうしますか？」を確認する（選択肢:
      `そのまま議題欄に転記する` / `空欄のままにする`）。議題として意味を成す
      本文が含まれていればそのまま転記する。
   3. いずれにも該当しない場合は空欄のままにする。
8. 作成したファイルパスをユーザーに報告する。
