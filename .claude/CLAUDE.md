# CLAUDE.md — このvaultの取扱説明書

個人利用のObsidian vault。Obsidian（Bases・デイリーノート・テンプレート）を
「見る場所」、Claude Codeを「操作・検出する場所」として役割分担する。

## 役割分担

- **Obsidianは見るための場所**: Bases・デイリーノートで「今の状態」を眺める。
- **Claude Codeは操作・検出のための場所**: 日々の面倒な操作（デイリーノート生成・
  ステータス更新）を担当する。加えて、Obsidian単体では検出できないこと
  （`context`が自動設定できなかったノート・カレンダーから無くなった議事録
  ノートの削除候補）も検出する。

## ノート種別とプロパティ

`type`プロパティで4種を判別する: `task` / `project`（旧project・areaを統合。
`due`が無ければ旧area相当） / `meeting` / `know-how`。`memo`は`type`プロパティを
持たず、`10_Inbox`・`20_Diary`のフォルダ基準で判別する。

| プロパティ | task | project | meeting | know-how | memo |
|---|---|---|---|---|---|
| type | ● | ● | ● | ● | |
| status | ●(1_todo/2_doing/3_pending/4_done/5_cancelled) | ●(1_active/2_done) | | | |
| due | ○ | ○ | | | |
| check | ○ | | | | |
| date | ● | | ● | ● | ● |
| context | ○ | ○ | ○ | ○ | ○ |

`tags`・`goal`は廃止済み。リンクは`context`（このノートが属する`project`ノートへの
単一リンク）のみを使う。横断的な分類・検索は全文検索に任せる。

## プロパティ更新はClaude Code経由を正とする

`status`/`check`をObsidianのプロパティパネルで直接書き換えることを
前提にしない。「Aタスクをdoingにして」のような自然言語の指示を受けたら、
該当ノートのfrontmatterを直接編集する。ステータス値は上表の許容値のみを使う。

## メモの運用

「メモしておいて」等の指示を受けたら、常に日次ノート（`20_Diary/<今日の日付>.md`）
の`## メモ`欄に追記することをデフォルトとする。`10_Inbox`への個別メモノート作成は、
ユーザーが明示的に「単独ノートにして」「Inboxに切り出して」等と指示した場合のみ、
`92_Template/memo.md`をもとに直接作成する。自動化する専用スキルは無く、都度の
指示ベースの操作とする。

## Git運用: 日次ブランチ

ノートを新規作成・編集するBash/Write/Edit操作を行う前に、必ず今日の日次
ブランチ（`daily/YYYY-MM-DD`）にいることを確認する。無ければ`main`から
`git checkout -b daily/<今日の日付>`で作成する。既に存在すればチェック
アウトするだけでよい。日中はコミットしない（`today`スキルの締め手順が最後に今日の
変更をひとつのコミットにまとめ、`main`へfast-forwardマージし、`git push`する）。

## コマンド

- `/today`: 当日のデイリーノートを開始・締め・更新する。トリガーフレーズで
  3モードを自動判別する（`.claude/skills/today/SKILL.md`にスキル化済み）。
  - **開始**: 新規作成・日次ブランチの作成/チェックアウト・カレンダー連携に
    よる議事録ノートの自動生成を行う。
  - **締め**: 今日作成・編集したノートの`context`補完・議事録アクション
    アイテムのタスク化・Teams/Copilot議事録の転記・今日のタスクの確認完了
    反映・明日の準備・今日作成/更新したノート一覧の最新化を行い、今日の
    変更をコミットして`main`へマージ・pushする。
  - **更新**: カレンダー・今日のタスク・今日作成/更新したノートのいずれか
    または全部を発言内容から判定して部分/全部更新する。判定できない場合は
    どの範囲を更新するか確認する。議事録ノートの自動生成・削除候補の確認を
    含む。
- `/intake`: メール・チャットで受けた依頼をタスクノート化する
  （`.claude/skills/intake/SKILL.md`にスキル化済み）。トリガーフレーズで2
  モードを自動判別する。
  - **貼り付けモード**: 会話に本文が貼られて「タスク化して」等と指示された
    場合。本文からタスク候補を抽出し、ユーザー確認を経て起票する。
  - **スキャンモード**: 「未処理メールからタスク候補を探して」等、本文の
    貼り付けが無い依頼の場合。利用可能なメール/チャットMCPツールで走査し
    （無ければ貼り付けモードを案内）、プロジェクトノートの
    `## コミュニケーション計画`にある件名ルールでcontextを自動割り振りする。
    frontmatter `source_id`（メッセージID）で起票済みメッセージを重複排除
    する。

各コマンドの詳細手順は、スキル化済みのものは`.claude/skills/<name>/SKILL.md`、
それ以外は`.claude/commands/`配下の対応するファイルを参照する。

## フォルダ

`60_Archive`は無い。完了は`status`で表現し、Basesの既定ビューは完了を除外表示にする
（「プロジェクト一覧」「タスク一覧」等。完了を含めて見たい時は「タスク：すべて
（完了含む）」「プロジェクト：すべて（完了含む）」ビューを使う）。
`type`はフォルダに依存せず判定されるため、`30_Work`配下はどうサブフォルダで
整理しても構わない。`30_Work`・`40_Knowledge`直下に置きっぱなしのノートを
プロジェクト・カテゴリのサブフォルダへ移す自動整理は現在は無く、手動で整理する。
`40_Knowledge`配下のサブフォルダ分類は、既存の類似カテゴリがあればそれを
優先して使い、類似概念の別名フォルダを新規に乱立させない。`10_Inbox`の
メモノート（`type`プロパティ無し）へのtype昇格を自動化する仕組みは無く、
必要であればユーザーが手動でtypeを付与し該当フォルダへ移動する。
