あなたはこのObsidian vaultの全タスクを対話的に棚卸する担当である。`/audit`
（読み取り専用の検出・報告のみ）とは異なり、こちらは検出した項目について
ユーザーと対話しながら実際に**追加・削除・更新**まで行う。`/wrapup`の
自動修正（今日の分だけ機械的に直す）とも異なり、こちらは**vault全体**を
対象に、人間の判断が要る項目をひとつずつ確認しながら進める。

**このコマンドは自動では何も変更・削除しない。すべてユーザーの確認・承認
を得てから実行する。**

## 手順

1. `30_Work/`配下の全`type: task`ノートを対象に、以下の観点で棚卸候補を
   抽出する。
   - **期限切れ**: `status`が`3_done`ではなく、`due`が今日より前
   - **チェック日超過**: `status`が`3_done`ではなく、`check`が今日より前
   - **長期放置**: `status`が`1_todo`のまま`date`から30日以上経過している
   - **優先順位未設定**: `status`が`3_done`ではなく、`due`・`check`が
     ともに空欄
2. `30_Work/`配下の全`type: meeting`ノートを対象に、`## アクションアイテム`
   見出し配下の未チェック`- [ ] [[ノート名]]`のうち、対応するタスクファイル
   が存在しないものを「未タスク化候補（追加候補）」として抽出する。
3. 抽出した候補を、種別ごと（期限切れ／チェック日超過／長期放置／未タスク化
   候補）にまとめてユーザーに提示する。
4. 種別ごとに、ユーザーに対応方針を確認する。
   - **期限切れ・チェック日超過・長期放置・優先順位未設定のタスク**: 「更新（`status`/
     `due`/`check`を変更）」「削除」「そのまま残す」のいずれかを
     ユーザーに選んでもらう。複数件まとめて同じ方針を指定してもよいし、
     1件ずつ確認してもよい（ユーザーの希望に従う）。
   - **未タスク化候補（議事録のアクションアイテム）**: `92_Template/task.md`
     を使ってタスク化するかどうかをユーザーに確認する。タスク化する場合は
     `context`をその議事録の`context`から継承する。
5. ユーザーが承認した内容のみ実行する（frontmatterの編集・ファイルの削除・
   新規タスクの作成）。削除は`git rm`ではなく`rm`でよい（このリポジトリの
   `main-branch-guard`により、削除前に日次ブランチへ切り替わっていることを
   前提とする。日次ブランチにいない場合はCLAUDE.mdの「Git運用: 日次ブランチ」
   の手順に従って先にブランチを用意する）。
6. 実行した変更（更新・削除・追加それぞれの件数と対象ノート名）をまとめて
   ユーザーに報告する。
